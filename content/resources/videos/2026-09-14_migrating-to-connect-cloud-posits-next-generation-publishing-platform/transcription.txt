<h3>Common migration failures</h3>

<p><a data-t="1800">Okay, I want to talk about a few things that might get in your way as you're going through this process.</a> <a data-t="1806">So there are some common migration failures that we see.</a> <a data-t="1809">The most common one is that you're going to get some kind of warning or error that a package that you depend on could not be downloaded or installed.</a></p>

<p><a data-t="1820">The first thing you want to do if there's an error, you're going to see failed, and you're going to see a link that says see logs.</a> <a data-t="1828">Taking you to see logs will show you the bottom of the logs from the deployment that did not, that was not successful.</a> <a data-t="1834">And you'll also see a dialogue box on the side that says, do you want to try to diagnose this problem with error assist?</a> <a data-t="1840">This is an optional AI-backed tool that can make it easier to understand what the logs are showing you and might help give you information to then go ahead and turn this failure into a successful migration that you can then test and finalize.</a></p>

<p><a data-t="1859">The most common way, as I mentioned, for a failure to occur right now is that these packages could not be found, and this especially happens with old applications.</a> <a data-t="1864">So if you have applications up on shinyapps.io that you haven't updated in six or seven years that are running old versions of R, that are running old, that were deployed from old operating systems, you're probably going to get some issues with system dependencies.</a></p>

<p><a data-t="1891">You might also find issues sitting around, you might be using a GitHub-specific private repo that might not have access to.</a> <a data-t="1901">You might be putting some things in the manifest, or there could be some things in these old manifests, especially, that specified base R packages or put something like Bioconductor, which is not a CRAN package, and they put it in the manifest as CRAN, and that kind of breaks a lot of the system.</a></p>

<p><a data-t="1922">To mitigate this, there are several things that you can attempt to do.</a> <a data-t="1928">Probably the easiest and most complete one is to refresh the dependencies.</a> <a data-t="1934">So find a way to update the packages, get new manifest requirement files.</a> <a data-t="1939">What I found is, for these really old ones, I will download it, I will download the bundle from shinyapps.io, I will bring it into RStudio or Positron.</a> <a data-t="1951">And if I don't have the deployment records for it, that's that's fine, but I will get it to be able to run right with a modern R version and a modern operating system.</a> <a data-t="1963">And I'm sure many of you have done this before.</a> <a data-t="1965">You run it, you'll probably see some failures that tells you to change this or change this.</a> <a data-t="1969">And then once you get it running locally again, you can either redeploy it to shinyapps.io, which is probably the safest thing to do if you wanna maintain that redirect we could put in place.</a> <a data-t="1981">Or you could say, the URL is not as important for this thing that I'm sharing, I'm just gonna deploy this directly to Connect Cloud.</a></p>

<p><a data-t="1991">Right now, Connect Cloud supports R version 4 to 4.6 and Python 3.9 to 3.14.</a> <a data-t="1997">If we attempt or if you attempt to migrate a piece of content that has a version below those levels, we will attempt to migrate it at the lowest next level up, right?</a> <a data-t="2007">So if you try to R 3.9, you would get to R 4.0.</a> <a data-t="2010">And that's kind of where these packaging consistencies come from at times.</a></p>
