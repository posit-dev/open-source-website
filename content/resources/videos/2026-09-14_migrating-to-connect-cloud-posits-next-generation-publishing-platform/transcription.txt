<h3>Connect Cloud history and free plan comparison</h3>

<h3>Common migration failures</h3>

<p><a data-t="1818">Okay, I want to talk about a few things that might get in your way as you're</a> <a data-t="1823">going through this process.</a> <a data-t="1823">So there are some common migration failures that we see.</a> <a data-t="1829">The most common one is that you're going to get some kind of warning or error</a> <a data-t="1834">that a package that you depend on could not be downloaded or installed.</a></p>

<p><a data-t="1840">The first thing you want to do if there's an error,</a> <a data-t="1843">you're going to see failed, and you're going to see a link that says see logs.</a> <a data-t="1843">Taking you to see logs will show you the bottom of the logs from the deployment that did not, that was not successful.</a> <a data-t="1854">And you'll also see a dialogue box on the side that says, do you want to try to diagnose this</a> <a data-t="1860">problem with error assist?</a> <a data-t="1860">This is an optional AI-backed tool that can make it easier to understand</a> <a data-t="1867">what the logs are showing you and might help give you information to then go ahead and turn this</a> <a data-t="1872">failure into a successful migration that you can then test and finalize.</a></p>

<p><a data-t="1872">The most common way, as I mentioned, for a failure to occur right now is that these packages could not be found,</a> <a data-t="1884">and this especially happens with old applications.</a> <a data-t="1884">So if you have applications up on shinyapps.io</a> <a data-t="1892">that you haven't updated in six or seven years that are running old versions of R,</a> <a data-t="1898">that are running old, that were deployed from old operating systems,</a> <a data-t="1902">you're probably going to get some issues with system dependencies.</a></p>

<p><a data-t="1907">You might also find issues sitting around, you might be using a GitHub-specific private repo</a> <a data-t="1914">that might not have access to.</a> <a data-t="1921">You might be putting some things in the manifest,</a> <a data-t="1923">or there could be some things in these old manifests, especially, that specified base R</a> <a data-t="1929">packages or put something like Bioconductor, which is not a CRAN package, and they put it</a> <a data-t="1934">in the manifest as CRAN, and that kind of breaks a lot of the system.</a></p>

<p><a data-t="1934">To mitigate this, there are several things that you can attempt to do.</a> <a data-t="1942">Probably the easiest and most complete one is to refresh the dependencies.</a> <a data-t="1948">So find a way to update the packages, get new manifest requirement files.</a> <a data-t="1954">What I found is, for these really old ones, I will download it, I will download the bundle</a> <a data-t="1959">from shinyapps.io, I will bring it into RStudio or Positron.</a> <a data-t="1966">And if I don't have the deployment records for it, that's that's fine, but I will</a> <a data-t="1971">get it to be able to run right with a modern R version and a modern operating system.</a></p>

<p><a data-t="1981">And I'm sure many of you have done this before.</a> <a data-t="1983">You run it, you'll probably see some failures</a> <a data-t="1984">that tells you to change this or change this.</a> <a data-t="1987">And then once you get it running locally again,</a> <a data-t="1989">you can either redeploy it to shinyapps.io,</a> <a data-t="1993">which is probably the safest thing to do</a> <a data-t="1994">if you wanna maintain that redirect we could put in place.</a> <a data-t="1997">Or you could say, the URL is not as important</a> <a data-t="2001">for this thing that I'm sharing.</a> <a data-t="2003">I'm just gonna deploy this directly to Connect Cloud.</a></p>

<p><a data-t="2007">Right now, Connect Cloud supports R version 4 to 4.6</a> <a data-t="2011">and Python 3.9 to 3.14.</a> <a data-t="2014">If we attempt or if you attempt to migrate</a> <a data-t="2017">a piece of content that has a version below those levels,</a> <a data-t="2020">we will attempt to migrate it</a> <a data-t="2022">at the lowest next level up, right?</a> <a data-t="2024">So if you try to R 3.9, you would get to R 4.0.</a> <a data-t="2030">And that's kind of where these packaging consistencies</a> <a data-t="2032">come from at times.</a></p>
