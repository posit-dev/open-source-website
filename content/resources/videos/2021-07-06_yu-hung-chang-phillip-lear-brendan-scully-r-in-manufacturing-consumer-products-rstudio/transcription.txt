<h3>Engine repair forecasting model</h3>

<p><a data-t="181">So starting off, the first tool I'm going to talk about</a> <a data-t="184">is an engine repair forecasting model.</a> <a data-t="186">This is the first tool that I worked on at Pratt,</a> <a data-t="190">and a brief background of Pratt &amp; Whitney</a> <a data-t="192">for those of you not familiar.</a> <a data-t="194">According to Wikipedia, Pratt &amp; Whitney</a> <a data-t="196">is an aerospace manufacturer with global service operations,</a> <a data-t="201">and, you know, what that means is we manufacture</a> <a data-t="203">and repair military and commercial engines,</a> <a data-t="206">and my role throughout my whole time at Pratt</a> <a data-t="208">has been focused on the commercial</a> <a data-t="210">aftermarket side of the business,</a> <a data-t="211">which includes maintenance, repair,</a> <a data-t="213">and overhaul of all of our engines.</a></p>

<p><a data-t="215">So one of the biggest questions that we focus on</a> <a data-t="218">on this side of the company is how many engines</a> <a data-t="222">can our global network of repair shops</a> <a data-t="224">repair in the upcoming year?</a></p>

<p><a data-t="228">This question is important because the repair shops</a> <a data-t="232">are giving annual and monthly repair goals</a> <a data-t="234">that their performance is evaluated against,</a> <a data-t="237">and throughout this planning process,</a> <a data-t="240">any shortfalls that are identified</a> <a data-t="242">then lead to a lot of the work</a> <a data-t="244">that goes on throughout the year,</a> <a data-t="246">from investing in new repair technology,</a> <a data-t="250">capacity constraints, and making decisions</a> <a data-t="254">to reallocate engines across the network.</a></p>

<p><a data-t="258">This question is also a complex question.</a> <a data-t="262">Repair performance and the number of engines</a> <a data-t="265">that our entire network can repair</a> <a data-t="267">is influenced by many interacting variables,</a> <a data-t="270">such as the type of repair being performed,</a> <a data-t="272">the turnaround time of each individual repair,</a> <a data-t="276">the capacity, not only at the shops themselves,</a> <a data-t="279">but within the different sections of each shop,</a> <a data-t="283">and existing work progress and backlogs.</a> <a data-t="286">So not an easy question to answer.</a></p>

<p><a data-t="291">The current state, I guess before I move on to the solution,</a> <a data-t="296">the current state that was in place</a> <a data-t="300">to answer this question was largely done</a> <a data-t="302">by taking the previous year's numbers</a> <a data-t="305">and increasing and decreasing that amount</a> <a data-t="307">based on knowledge of changes in the business,</a> <a data-t="310">conversations with the general managers</a> <a data-t="311">at all the repair shops.</a> <a data-t="313">What lacked was a rigorous quantified justification</a> <a data-t="318">behind these numbers.</a></p>

<p><a data-t="322">And so what Pratt wanted was to make an answer</a> <a data-t="325">to this question more robust and defendable</a> <a data-t="329">by giving it a quantified justification.</a></p>

<p><a data-t="332">So the solution that I developed</a> <a data-t="335">that helps answer this question</a> <a data-t="337">is a simulation-based forecasting model using R</a> <a data-t="344">that has been hosted on RStudio Connect.</a> <a data-t="347">So what this model does</a> <a data-t="348">is it takes our global network of repair shops</a> <a data-t="351">and models the flow of engines</a> <a data-t="353">from the wing of the airplane</a> <a data-t="355">through each stage of the repair journey</a> <a data-t="357">all the way through the delivery to customer</a> <a data-t="360">using a Markov decision process.</a></p>

<p><a data-t="363">So the diagram on the right,</a> <a data-t="364">I know the text is small</a> <a data-t="366">and it's not really meant to be read,</a> <a data-t="368">but it shows how the process is mapped out at a high level</a> <a data-t="373">where each stage of the repair journey is given a state</a> <a data-t="378">and then the flow of the engines from state to state</a> <a data-t="382">is then governed by rules.</a></p>

<p><a data-t="386">And those rules are all dependent</a> <a data-t="389">on a large number of inputs from the turnaround time.</a> <a data-t="394">So the capacity of the shops to the work in progress</a> <a data-t="398">to the induction plan,</a> <a data-t="400">to the engines currently sitting outside the shop</a> <a data-t="402">and backlog.</a> <a data-t="404">And so one thing this model allows Pratt to do now</a> <a data-t="410">is instead of talking about it as a whole</a> <a data-t="413">and doing all that thinking in your head,</a> <a data-t="415">we can have focused conversations on individual inputs</a> <a data-t="418">like the capacity of this section of the shop,</a> <a data-t="420">has that increased or decreased?</a> <a data-t="423">The turnaround times,</a> <a data-t="424">are we expecting similar turnaround times</a> <a data-t="425">on these repairs this year as opposed to next year?</a> <a data-t="428">And then roll all of those inputs and conversations</a> <a data-t="433">up to the model,</a> <a data-t="435">which will then output a final number</a> <a data-t="440">for engines inducted and returned.</a></p>

<p><a data-t="443">So the main benefit is it offers a quantified justification</a> <a data-t="448">for annual and monthly repair goals.</a> <a data-t="450">And then it also allows for sensitivity analysis</a> <a data-t="454">and scenario testing.</a></p>

<p><a data-t="458">This has taken the shape of</a> <a data-t="460">how does increasing the capacity of this shop</a> <a data-t="462">actually impact the number of engines</a> <a data-t="465">we get to repair as a whole.</a> <a data-t="467">Or scenario testing,</a> <a data-t="468">which came into play last year</a> <a data-t="472">as COVID hit the airline industry.</a> <a data-t="474">We had to rapidly change our goals</a> <a data-t="476">and adapt to a new environment,</a> <a data-t="479">new demand and new capacity</a> <a data-t="482">as a lot of our workforce was reduced.</a> <a data-t="484">And so this model quickly allowed us</a> <a data-t="487">to run many different scenarios in a short period of time,</a> <a data-t="492">which is something we weren't able to do before.</a></p>

<p><a data-t="495">The last benefit is having the graphical user interface</a> <a data-t="499">on RStudio so that ultimately</a> <a data-t="502">I'm not the end user of this model</a> <a data-t="504">and the end user of this model</a> <a data-t="508">doesn't have strong background in R</a> <a data-t="511">and can operate and use the model</a> <a data-t="514">through RStudio Connect and the graphic user interface.</a></p>

<h3>Decision analytics hierarchy of needs</h3>

<p><a data-t="914">So moving on to my role in the strategy team</a> <a data-t="920">is I've kind of taken a step back</a> <a data-t="921">from the individual tools and taken a higher level view</a> <a data-t="925">and trying to work on ways that Pratt can prioritize</a> <a data-t="932">decision analytics projects and best use them.</a> <a data-t="935">And one framework that's helped me think</a> <a data-t="937">about these projects is the decision analytics hierarchy</a> <a data-t="940">of needs based loosely off Maslow's hierarchy of needs.</a></p>

<p><a data-t="945">The idea here being each level of the pyramid</a> <a data-t="949">needs to be addressed before the other one</a> <a data-t="951">can even be worked on.</a> <a data-t="953">And the way I've broken it down</a> <a data-t="955">and the way I see a lot of projects at Pratt</a> <a data-t="959">are data storage and organization is the first step</a> <a data-t="965">and the most important step that needs to be addressed.</a> <a data-t="968">Data relevant to your project or your business need</a> <a data-t="973">needs to be stored and organized</a> <a data-t="975">in an effective and thoughtful way.</a></p>

<p><a data-t="980">However, storage and organization is not enough.</a> <a data-t="983">There then needs to be data accessibility in place.</a> <a data-t="987">So what's required to make the data</a> <a data-t="989">accessible to stakeholders?</a> <a data-t="991">That could be literal access, access approval,</a> <a data-t="998">having the credentials or tools</a> <a data-t="1002">you need to access the database.</a> <a data-t="1004">But it also means is it stored in a way that is accessible?</a> <a data-t="1007">Is it in, there's a team here that has a lot</a> <a data-t="1013">of repair information stored in PDFs.</a> <a data-t="1015">Well, it's stored, but it's not accessible</a> <a data-t="1017">in a meaningful way.</a></p>

<p><a data-t="1022">The last step then is when you have successful data storage</a> <a data-t="1026">and accessibility is then building the analytics tools</a> <a data-t="1031">and then implementing data-driven decisions.</a> <a data-t="1034">So how can the data then be used to serve our needs</a> <a data-t="1037">and make better decisions?</a> <a data-t="1039">A lot of times there's a lot of talk and focus</a> <a data-t="1042">on the top of the pyramid without full understanding</a> <a data-t="1045">and focus on data accessibility and data storage.</a> <a data-t="1048">So this is a framework that I find useful</a> <a data-t="1051">to level set expectations for a project</a> <a data-t="1057">and then direct the right resources</a> <a data-t="1059">to the right problems before starting a project.</a></p>

<blockquote><a data-t="1039">A lot of times there's a lot of talk and focus</a> <a data-t="1042">on the top of the pyramid without full understanding</a> <a data-t="1045">and focus on data accessibility and data storage.</a></blockquote>

<h3>Common challenges at Pratt</h3>

<p><a data-t="1064">And then this last slide here are some common challenges</a> <a data-t="1068">that I've faced during my time at Pratt</a> <a data-t="1070">and I'm sure are not specific to Pratt.</a> <a data-t="1074">I also talk about some of the approaches</a> <a data-t="1078">that we've taken here to address these issues.</a> <a data-t="1082">They're by no means the right answer</a> <a data-t="1084">or even the only right answer</a> <a data-t="1087">or even complete answers to the problems,</a> <a data-t="1089">but they are steps that we've taken that have helped us.</a></p>

<p><a data-t="1094">So one of the biggest common challenges</a> <a data-t="1096">is lack of engagement from all stakeholders.</a> <a data-t="1099">And I see I'm running a bit short on time,</a> <a data-t="1101">so I will rattle through this somewhat quickly,</a> <a data-t="1104">but there's two main cases that we've identified</a> <a data-t="1110">or I've noticed here,</a> <a data-t="1112">and that's analytics tools developed</a> <a data-t="1114">without enough input from the end user.</a> <a data-t="1117">This usually means or results in the business needs</a> <a data-t="1121">not being addressed by the tool directly</a> <a data-t="1124">and ultimate ownership and integration</a> <a data-t="1126">of the tool into business processes</a> <a data-t="1129">becomes unclear and difficult.</a></p>

<p><a data-t="1132">The other type of issue of lack of engagement</a> <a data-t="1135">from all stakeholders is analytics tools being developed</a> <a data-t="1139">by the business users, in our case, the repair shops</a> <a data-t="1142">without involvement of the central technology team.</a> <a data-t="1147">This usually leads to fragile and fragmented architecture,</a> <a data-t="1150">manual data transfer, copying of Excel files and CSV files</a> <a data-t="1155">and an inefficient use of resources.</a></p>

<p><a data-t="1199">Finally, or secondly,</a> <a data-t="1205">to encourage the business users</a> <a data-t="1208">to involve the digital technology team,</a> <a data-t="1211">regular communications to understand business needs</a> <a data-t="1213">and capabilities should be established.</a> <a data-t="1215">We did this in the form of phone calls</a> <a data-t="1217">to all our repair sites to understand their needs</a> <a data-t="1222">and talk about our capabilities.</a> <a data-t="1225">And then the big thing here is organic involvement</a> <a data-t="1227">of the digital technology team through a series of successes.</a> <a data-t="1232">So have the business users organically</a> <a data-t="1235">come to the digital technology team</a> <a data-t="1237">because you've delivered value in the past.</a></p>
