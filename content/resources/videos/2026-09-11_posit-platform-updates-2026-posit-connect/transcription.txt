<p><a data-t="0">We've released a lot of new great stuff in Connect</a> <a data-t="2">over the last couple of months,</a> <a data-t="4">but the one thing that I want to demo today</a> <a data-t="7">is my new favorite way to do publishing in Connect.</a> <a data-t="11">It's called Trusted Publishing,</a> <a data-t="13">and it helps you go from manual deployment</a> <a data-t="17">of a content asset</a> <a data-t="19">to keyless GitHub Action-style pipeline deployment.</a> <a data-t="24">And by keyless here, we mean that you're no longer required</a> <a data-t="27">to use a Connect API key to drive your deployments.</a></p>

<h3>Setting up trusted publishing</h3>

<p><a data-t="86">So setting this up is pretty simple.</a> <a data-t="89">We've tried to make this as simple as possible.</a> <a data-t="91">It's available and enabled by default in the July release,</a> <a data-t="97">but it's only available for enhanced</a> <a data-t="99">and advanced Connect licenses right now.</a> <a data-t="103">So you'll deploy your content once,</a> <a data-t="106">you set up your GitHub repository,</a> <a data-t="109">you set up trusted publishing on the Connect side,</a> <a data-t="112">you set up your scaffold for GitHub actions</a> <a data-t="116">or whatever pipeline you're building.</a> <a data-t="118">We have a new Connect action skill</a> <a data-t="121">that makes this really easy.</a> <a data-t="124">You don't forget to pin your dependencies,</a> <a data-t="126">even though you've used something</a> <a data-t="128">maybe like push-button deployment,</a> <a data-t="129">you still need to have a manifest or requirements file</a> <a data-t="133">in the repository for this to function,</a> <a data-t="135">and then you run it.</a></p>
