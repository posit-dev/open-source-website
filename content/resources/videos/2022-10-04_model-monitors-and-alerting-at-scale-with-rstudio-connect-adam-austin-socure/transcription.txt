<h3>What is a monitor?</h3>

<p><a data-t="414">All right.</a> <a data-t="414">So first of all, model monitoring and alerting, what does that even mean?</a> <a data-t="418">So what is a monitor?</a> <a data-t="418">In its simplest terms, to me, a monitor is a visual presentation of model metrics that is refreshed regularly and will notify you if something is wrong.</a> <a data-t="433">This is sort of the three components I think of when I think of monitoring.</a> <a data-t="433">So basically, making sure that everything is running smoothly.</a> <a data-t="438">And it's a place you can go to visually see what's happening.</a> <a data-t="444">It's something that should be constantly updating, so it's always kept current, so you're never caught off guard by anything that goes wrong.</a> <a data-t="449">And it should alert you if things do go wrong.</a></p>

<p><a data-t="453">So I use that word alert.</a> <a data-t="453">What actually is an alert?</a> <a data-t="453">So this is going to be some kind of notification of abnormal data inputs or perhaps model outputs.</a> <a data-t="458">And you want to be alerted if something goes wrong so that you can respond quickly.</a> <a data-t="467">Maybe you need to retrain your models, or maybe you need to look into a problem with an upstream data source, or maybe you just need to communicate with a customer.</a> <a data-t="476">Or in our case, in Socure's case, we want to communicate with the customer and say, hey, we noticed that our scores are changing.</a> <a data-t="487">Is something different on your end, or should we do some more digging on our end?</a></p>

<p><a data-t="492">So an example of an alert might be, you know, suddenly you're getting too few records from an input data source.</a> <a data-t="498">Maybe you have just sudden spike in bad input data, so too many missing values.</a> <a data-t="504">Maybe you're getting the wrong factor levels coming through and your model can't score those.</a> <a data-t="508">Maybe you have certain input values that are exceeding expected thresholds, so they're too high, they're too low, and that just looks weird to you.</a> <a data-t="514">And also, very importantly, you want to make sure that your models are producing the right kinds of scores.</a> <a data-t="520">So when you're building a model and vetting it, you're going to produce a sort of certain expected distribution of model scores, and you want to make sure that those things don't change over time through, you know, drift in the kinds of records you're scoring and that sort of thing.</a> <a data-t="534">So if your model scores change considerably, that might have impacts in Socure's case for our clients in terms of how they're thinking about their customers, so you want to make sure that we alert them to that.</a></p>

<h3>Using R Markdown for monitoring</h3>

<p><a data-t="555">All right, so how are we actually going to do this monitoring and alerting?</a> <a data-t="555">Well, this is a great job for R Markdown, or of course, </a><a href="/software/quarto/">Quarto</a><a data-t="555"> is sort of the new R Markdown, if you will.</a> <a data-t="559">It's a bit of a replacement for R Markdown, but when we were developing this system, we've been using R Markdown, and it works really well for us.</a> <a data-t="574">So why would we use R Markdown in this case?</a> <a data-t="574">Well, it has, obviously, infinite flexibility.</a> <a data-t="579">You can compute any function of your data.</a></p>

<p><a data-t="586">And this is important because there are a lot of really great monitoring solutions out there.</a> <a data-t="591">Different kinds of companies provide ways for you to monitor your data and your models.</a> <a data-t="597">A lot of those solutions are a little bit limited in how you actually compute functions of your data.</a> <a data-t="608">So maybe you're forced into using certain kinds of SQL queries, or maybe you're forced into using a kind of certain proprietary language to compute and construct your statistics, and that can be a little bit limiting.</a> <a data-t="620">With R Markdown, you're just using R or even Python if you want, and so you can compute any function of your data.</a></p>

<p><a data-t="633">R Markdown is great for hosting because you can publish and refresh your reports on RStudio Connect, and we'll see more about that in just a minute.</a> <a data-t="638">And R Markdown is really nice because R has a huge suite of integrations.</a> <a data-t="644">You can choose to send out alerts via email.</a> <a data-t="644">You can use Slack.</a> <a data-t="651">You can use GChat.</a> <a data-t="651">You can use Microsoft Teams, and so on and so forth.</a> <a data-t="651">There's all kinds of great integrations where you can choose different channels to send your alerts to based on your needs.</a> <a data-t="660">I think email is nice because even though it requires more setup to get going, I think there's a bit more flexibility in what you can report to end users there, and it also allows your users who are receiving these alerts to use advanced filtering and things like that to meet their own needs.</a></p>
