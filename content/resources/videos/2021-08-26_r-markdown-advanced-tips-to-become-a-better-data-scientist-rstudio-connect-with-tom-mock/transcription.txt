<h3>Literate programming</h3>

<p><a data-t="250">The first one, and I think the obviously one of the core workflows that you're going to do in</a> <a data-t="255">R Markdown, is literate programming. The goal here is that you're going to capture your code,</a> <a data-t="262">text, or comments, and your output in a single document. So you have essentially like this</a> <a data-t="267">reproducible workflow of capturing your code, along with the output, along with any kind of</a> <a data-t="273">comments about what the code is doing, or the outputs that you're seeing, all together. So you</a> <a data-t="277">can share one document, or one report with someone if you wanted to do that. But you can also</a> <a data-t="281">reproduce it, because you have the source code. The idea of literate programming has been around</a> <a data-t="288">for a long time. Donald Knuth has this nice quote about literate programming as a programming</a> <a data-t="295">paradigm. And the explanation of it is that it's logic in a natural language, such as English,</a> <a data-t="301">interspersed with snippets of macros and traditional source code, from which the</a> <a data-t="305">compilable source code can be generated.</a></p>

<p><a data-t="305">Now when we think about source code in R,</a> <a data-t="309">we have code chunks.
