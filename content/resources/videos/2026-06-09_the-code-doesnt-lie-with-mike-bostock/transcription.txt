<h3>Observable's reactive notebook model</h3>

<p><a data-t="1881">So Observable started as this way of like, how can I make programming more accessible?</a> <a data-t="1887">Like moving it to the web, so you don't need any development environment.</a> <a data-t="1891">But it was also, in a way, like rethinking some of the aspects of programming.</a> <a data-t="1896">So yes, it's a computational notebook, you know, like Jupyter, you have cells, you can</a> <a data-t="1902">run cells, and they can display things, and they can compute values.</a> <a data-t="1905">But I think one of the key differences, one of the key innovations of the Observable notebook</a> <a data-t="1909">was reactivity.</a></p>

<p><a data-t="1911">This idea, like in a spreadsheet, where you don't have to manually run the cells, that</a> <a data-t="1916">instead, it understands the topological relationships.</a> <a data-t="1919">So if you declare a variable in one cell, and then you reference it in another cell,</a> <a data-t="1925">when you redefine that variable, any referencing cell runs automatically.</a> <a data-t="1929">And it's just like kind of a bookkeeping thing, in a sense, where like, you as the author</a> <a data-t="1934">of your program, don't have to remember to keep rerunning things, or worry about being</a> <a data-t="1939">in this kind of inconsistent state where you've changed the code, but you've forgotten to</a> <a data-t="1943">rerun certain downstream cells, and so like, it's not matching up what you expect.</a></p>

<p><a data-t="1947">So like, spreadsheet programming, I think, has made that form of programming much more</a> <a data-t="1952">accessible.</a> <a data-t="1953">But you only have these tiny little cells that can produce numbers, and in a sense,</a> <a data-t="1957">I just wanted bigger cells that could produce graphical outputs as well.</a></p>

<p><a data-t="1962">And the other thing that comes along with this reactivity model is basically anything</a> <a data-t="1966">can become user controlled, anything that can become interactive.</a> <a data-t="1971">And so you can take, you know, a number, like, let's say you're building an inflation calculator</a> <a data-t="1975">or something, and you want to, like, have a given a certain amount in a certain year,</a> <a data-t="1980">and you want to say, like, what is that value in today's dollars, rather than having to</a> <a data-t="1984">edit the code to change what the number is, like, just replace that with a slider.</a> <a data-t="1989">And because it's reactive, you don't have to change anything downstream, like any constant</a> <a data-t="1993">variable can be turned into something that's interactive, or turned into something that's</a> <a data-t="1996">animated and stuff like that.</a></p>

<p><a data-t="1998">And my because my experience from D3 was a lot of that kind of interactivity, like the</a> <a data-t="2004">asynchronous nature of loading data, and kind of handling all of these different states,</a> <a data-t="2009">like that was the hardest part, in a way, about making interactive visualizations.</a> <a data-t="2014">And so if you could handle that at the language layer, or by with the runtime, then it's kind</a> <a data-t="2019">of a simpler way of thinking about it.</a></p>
