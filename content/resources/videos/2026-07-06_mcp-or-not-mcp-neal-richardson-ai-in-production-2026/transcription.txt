<h3>What MCP is (and isn't)</h3>

<p><a data-t="315">I've said MCP a bunch of times, I should probably say what it is, MCP model context protocol.</a> <a data-t="321">Uh, I've talked to a lot of people in a lot of different industries about this lately, and I've found a lot of confusion about what it is.</a> <a data-t="328">And so I first want to say what MCP is not.</a> <a data-t="331">It is not magic illusions.</a> <a data-t="334">It's not AI.</a> <a data-t="336">It's not vector search.</a> <a data-t="338">It's not any of these things.</a> <a data-t="339">You could put vector search behind an MCP server.</a> <a data-t="342">You could put AI behind an MCP server.</a> <a data-t="344">But MCP is really just a specification for how to provide tools to LLMs.</a> <a data-t="350">So tools are functions that an LLM can call.</a></p>

<p><a data-t="353">And the definitions of these tools, uh, are in the kind of start of the context window that you have.</a> <a data-t="360">And so a model will see that a function exists by this name.</a> <a data-t="364">Here's a description of what it does and what inputs it takes and that kind of thing.</a> <a data-t="367">So MCP is a standard for, uh, developing servers that provide those tools and for client applications, any AI application to use them.</a> <a data-t="376">I was talking about Claude Code and that was the example I showed there, but it's not limited to code.</a> <a data-t="379">AI applications, any AI application that supports MCP can use MCP servers.</a> <a data-t="384">They don't have to be about writing code.</a></p>

<h3>Best practices: brevity and security</h3>
