<h3>What is an API?</h3>

<p><a data-t="412">And that's really where APIs come in.</a> <a data-t="412">So let's take a step aside from the model for a moment,</a> <a data-t="417">and let's just talk about this notion of what an API is.</a> <a data-t="417">And in general, an API stands for</a> <a data-t="424">Application Programming Interface.</a> <a data-t="424">Now that can mean a lot of different things, and in different</a> <a data-t="429">contexts the idea of an API can mean different things, which makes it a little bit difficult</a> <a data-t="433">to understand.</a> <a data-t="433">And so for the purpose of our conversation today, we're going to narrow in</a> <a data-t="438">on this definition that an API is a web API communicating over HTTP.</a> <a data-t="438">And basically what</a> <a data-t="448">that is, is that provides us with a standardized way for different computers to communicate with</a> <a data-t="454">one another.</a> <a data-t="454">And I'm not going to dive into the nitty-gritty details of what makes up an API</a> <a data-t="459">request and what a response looks like.</a> <a data-t="459">There's lots of different features involved here that</a> <a data-t="463">you can look into, and that will provide some resources that provide some detail there.</a></p>

<p><a data-t="467">But the main idea is when we talk about web APIs over HTTP, which is what we're going to talk</a> <a data-t="473">about today, this is just a standardized set way for different computers to communicate.</a> <a data-t="473">Just like</a> <a data-t="480">I'm communicating now through my voice, and you're able to understand, computers have their own way</a> <a data-t="486">of communicating.</a> <a data-t="486">HTTP web APIs is one of those mechanisms for communication.</a> <a data-t="486">The idea is there's</a> <a data-t="493">a client that sends a request, that request meets the standard of what the server is expecting,</a> <a data-t="500">and then a server receives that request and then generates some sort of a response.</a> <a data-t="504">And that response could be something as simple as, I received the request, that's all I need,</a> <a data-t="509">that's all I need to do.</a> <a data-t="509">To something that's much more complex, like firing off some sort of process</a> <a data-t="513">or updating a database or generating predictions against the model, or any number of different</a> <a data-t="518">things can happen in response to a request that comes in.</a> <a data-t="518">But the server is responsible for taking</a> <a data-t="524">the request and doing something with it and then providing a response.</a></p>

<p><a data-t="524">And even if you've never</a> <a data-t="529">really interacted directly, knowingly with APIs in the past, it's interesting to note that</a> <a data-t="536">anytime you use a web browser, so if you use Google Chrome or Safari or Brave or Firefox or anything</a> <a data-t="542">like that, and you visit a website, there's a request that your web browser makes to a server</a> <a data-t="548">that says, hey, I'd like to view this web page that's at this address, and the server responds</a> <a data-t="554">with typically a bunch of HTML that your browser then renders for you to view.</a> <a data-t="554">So anytime you view</a> <a data-t="559">a website, you're really interacting with APIs, even if you don't acknowledge that fact, right?</a> <a data-t="564">Your computer is a client and it's sending a request, and there's a server somewhere that's</a> <a data-t="568">responding to that request with some HTML that you view as the web page.</a> <a data-t="568">Now, this is, again,</a> <a data-t="574">not meant to be a comprehensive overview of what APIs are or how APIs work, but this hopefully sets</a> <a data-t="581">the stage and gives you a little bit of background.</a></p>
