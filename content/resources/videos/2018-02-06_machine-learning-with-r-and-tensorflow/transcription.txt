<h3>What is TensorFlow?</h3>

<p><a data-t="91">So let's start with what is TensorFlow.</a> <a data-t="93">And you might offhand just say, oh, TensorFlow, that's a deep learning library.</a> <a data-t="99">It is that, but it's actually considerably more than that.</a> <a data-t="103">TensorFlow is actually a very general purpose numerical computing library.</a> <a data-t="108">And in R, we have a long history of providing interfaces to numerical computing libraries.</a> <a data-t="114">The original S language was the motivator for it was to provide interfaces to Fortran</a> <a data-t="120">numerical computing libraries.</a> <a data-t="122">And today in R, we wrap that code, we wrap code from Blasses, we wrap code from the Eigen</a> <a data-t="128">C++ library, the Armadillo C++ library.</a> <a data-t="132">In R, we love numerical computing libraries, and we love creating lovely interfaces to</a> <a data-t="135">them from R.</a></p>

<p><a data-t="137">So this is a new numerical computing library, and it has some interesting attributes.</a> <a data-t="140">First of all, it's open source, as I said before.</a> <a data-t="143">Second of all, it's actually hardware independent.</a> <a data-t="145">So a TensorFlow program can run equally well on a CPU and take advantage of all the cores</a> <a data-t="152">on a CPU, and that's actually using the Eigen and Blass libraries that we already use from</a> <a data-t="157">R.</a> <a data-t="158">But it can also run on a GPU or multiple GPUs.</a> <a data-t="162">And there's even a thing that Google has created called a TPU, a tensor processing unit, which</a> <a data-t="166">is hardware that is designed to run TensorFlow programs.</a> <a data-t="170">And there will actually be other instances of this in the future.</a> <a data-t="173">So hardware independence is a really cool attribute of TensorFlow.</a></p>

<p><a data-t="176">Another really cool attribute of it for numerical computing is that it supports automatic differentiation.</a> <a data-t="181">And that's used extensively in the deep learning parts of TensorFlow.</a> <a data-t="186">The other thing is it was built from the ground up for deployment, and scalable deployment,</a> <a data-t="192">so it supports distributed execution, it supports very, very large datasets.</a> <a data-t="195">So it's a really cool numerical computing library that we can do a lot of things with</a> <a data-t="198">in R.</a></p>

<p><a data-t="201">And that's kind of the first bullet point of why our users should care.</a> <a data-t="204">New numerical computing library, what can we do with it?</a> <a data-t="207">One of the other cool things about it is that there are many built-in optimization algorithms</a> <a data-t="213">that don't require that all the data is in RAM.</a> <a data-t="215">So typically, the optimization algorithms we use require that we manage to get the whole</a> <a data-t="219">dataset in RAM.</a> <a data-t="220">But now we can have a 10 gigabyte dataset, and we actually feed data to models just a</a> <a data-t="225">small batch at a time, and the optimizer will work correctly.</a> <a data-t="228">So it lets us do modeling and machine learning on very large datasets without having to have</a> <a data-t="233">a huge amount of RAM.</a></p>

<p><a data-t="235">Another piece of TensorFlow that's interesting is that typically when we think about building</a> <a data-t="238">a model in R and then we want to deploy it, we actually need to bring R code along with</a> <a data-t="242">it in the deployment.</a> <a data-t="244">But the whole design of TensorFlow is that when you build a TensorFlow model, you can</a> <a data-t="248">deploy it entirely separate.</a> <a data-t="250">You don't need R or Python or any other code.</a> <a data-t="252">It's just a C++ runtime.</a> <a data-t="253">So this is actually really cool, too.</a> <a data-t="255">So the last piece, I think we're really good in R at writing interfaces to all kinds of</a> <a data-t="262">things in computing, and I think we can do a lot of wonderful things with R interfaces</a> <a data-t="266">to TensorFlow.</a></p>

<h3>Introduction to deep learning</h3>

<p><a data-t="624">OK, so now let's get into a little bit of what,</a> <a data-t="628">because deep learning is probably the main thing people do with TensorFlow.</a> <a data-t="631">And so I think it's important to understand kind of what is it?</a> <a data-t="634">What is it useful for?</a> <a data-t="634">What is it not useful for?</a> <a data-t="636">Should we in the R community, how much should we care about it?</a> <a data-t="639">And kind of how does it work?</a> <a data-t="641">So I want to cover some of that ground.</a> <a data-t="643">And then I'll talk about the R interfaces to TensorFlow.</a></p>

<p><a data-t="646">So at a really, really high level, deep learning</a> <a data-t="652">is taking some input, transforming it into some output</a> <a data-t="655">via successive layers of representation.</a> <a data-t="658">And when I say this really abstract to say input and output, what I mean there</a> <a data-t="661">is like observations or x data and predictions.</a> <a data-t="664">So it's x to y, but how do we do that?</a> <a data-t="668">We do that by taking original input, in this case,</a> <a data-t="671">a grayscale image of a handwritten number 4.</a> <a data-t="675">That's our input, and our output is a prediction about what the digit is,</a> <a data-t="677">the number 4.</a> <a data-t="679">We have to successfully transform that input until we get close to the output.</a> <a data-t="683">That's the basic mechanic of how deep learning models work.</a></p>

<p><a data-t="687">So I'm talking about layers.</a> <a data-t="688">I showed four layers there.</a> <a data-t="689">What exactly is a layer?</a> <a data-t="692">And I'm not going to talk about the mechanics of, maybe some of you</a> <a data-t="694">have seen this before, of neurons and how they talk to other neurons</a> <a data-t="697">and all that stuff.</a> <a data-t="698">You can really just think of a layer, and all you really</a> <a data-t="701">need to consider a layer as, it's a function.</a> <a data-t="703">It's a data transformation function.</a> <a data-t="704">It does a geometric transformation of data,</a> <a data-t="707">and it's parameterized by a set of weights and a bias,</a> <a data-t="710">just like a linear equation.</a> <a data-t="712">So you can think of each one of these as just a successive transformation</a> <a data-t="715">of data.</a> <a data-t="716">So that's all a deep learning model is, is taking some data</a> <a data-t="719">and then chaining together a bunch of transformations of the data</a> <a data-t="723">until we actually get an output, or in this case, a prediction.</a></p>

<p><a data-t="727">So when I say representations, what am I talking about?</a> <a data-t="729">We really want to take our data and transform it</a> <a data-t="732">in a way that's closer to the domain of prediction that we're looking for.</a> <a data-t="738">So this is a really simple example.</a> <a data-t="739">I've got raw data.</a> <a data-t="740">I've got a bunch of points, and I want to determine</a> <a data-t="744">whether a point, be able to predict whether a point is black or white.</a> <a data-t="747">If I change the coordinate system, all of a sudden,</a> <a data-t="750">the problem becomes really simple, because everything</a> <a data-t="753">with x greater than zero is a black point,</a> <a data-t="755">and everything with x less than zero is a white point.</a> <a data-t="759">So the idea is we want to transform our data</a> <a data-t="761">so it's easier and easier to get close to the actual output</a> <a data-t="765">that we're looking for, the prediction that we're looking for.</a></p>

<p><a data-t="767">If you work with conventional machine learning models,</a> <a data-t="770">you'll know this as sort of feature engineering, where</a> <a data-t="773">we're trying to transform our data into a form that</a> <a data-t="775">works better for the prediction task.</a> <a data-t="778">And in deep learning, the feature engineering</a> <a data-t="780">is actually done in the layers.</a> <a data-t="782">The feature engineering is actually learned rather than hand coded.</a></p>

<blockquote><a data-t="782">The feature engineering is actually learned rather than hand coded.</a></blockquote>

<p><a data-t="787">So back to this example of the handwritten digits,</a> <a data-t="790">and I'll explain a little bit later how this works.</a> <a data-t="793">But basically, we're taking raw data, and these layers</a> <a data-t="797">are trying to filter out irrelevant information,</a> <a data-t="799">like how the image actually looks.</a> <a data-t="802">And it's trying to find other things, like where are edges, what</a> <a data-t="805">are the angle of the edges, and get closer and closer</a> <a data-t="807">to the domain of output or prediction.</a> <a data-t="810">So you can think of it as sort of an information distillation pipeline.</a></p>

<p><a data-t="815">And so this gives us an intuition about where the word deep comes from.</a> <a data-t="819">Why do we call this deep learning?</a> <a data-t="820">It's not because it gives us deeper insight or deeper models.</a> <a data-t="825">It's really just talking about the fact that there's</a> <a data-t="827">multiple layers of representation.</a> <a data-t="829">A traditional machine learning model might have some feature engineering,</a> <a data-t="832">and then one or two layers.</a> <a data-t="833">A deep learning model could have 20 layers, or 30 layers, or 100 layers.</a> <a data-t="838">And so maybe a more accurate term for deep learning</a> <a data-t="840">might be like layered representation learning,</a> <a data-t="842">or hierarchical representation learning.</a> <a data-t="844">The deep learning maybe implies more than it should,</a> <a data-t="847">but it's really just talking about the stacking up of layers.</a></p>

<p><a data-t="851">And so what has this method achieved?</a> <a data-t="856">And you can see from the list here, it's</a> <a data-t="859">done really, really well on a lot of perceptual tasks,</a> <a data-t="862">like speech recognition and image classification.</a> <a data-t="866">And then those, in turn, have been composed together</a> <a data-t="868">to do things like trying to build autonomous driving systems,</a> <a data-t="872">to build reinforcement learning systems that play games.</a> <a data-t="875">So it's achieved a lot, this fairly straightforward mechanism.</a> <a data-t="879">And to give you an intuition for why it might be able to do that,</a> <a data-t="882">if you think about a paper ball that's crumpled up,</a> <a data-t="885">and you think about trying to write a linear equation for how</a> <a data-t="888">to uncrumple the paper ball, it would be really, really difficult to do that.</a> <a data-t="892">But if you decompose the un, it's a really complex geometric transformation</a> <a data-t="896">to uncrumple that whole ball.</a> <a data-t="898">But if you decompose it into a set of simpler geometric transformations,</a></p>

<p><a data-t="902">i.e. layers, then it's actually straightforward.</a> <a data-t="905">So a human being might just take that paper ball,</a> <a data-t="907">and in 30 or so really simple operations, uncrumple it.</a> <a data-t="910">And that's really how deep learning models work,</a> <a data-t="912">is that they learn these simple geometric transformations that</a> <a data-t="916">compose together can do very, very complex transformations,</a> <a data-t="920">and therefore solve very complex functions,</a> <a data-t="923">or fit very complex functions.</a></p>

<p><a data-t="926">So why should we care about this?</a> <a data-t="928">I actually think the domains that deep learning</a> <a data-t="931">is proven to perform well in are ones that are not</a> <a data-t="934">often of interest to R users.</a> <a data-t="937">So these perceptual tasks, like vision and speech recognition,</a> <a data-t="941">and these reinforcement learning applications,</a> <a data-t="943">they're not things that most R users are concerned with.</a> <a data-t="947">So it may be that as an R user, you think</a> <a data-t="949">it's cool that you can now do state of the art computer vision from R.</a> <a data-t="953">But it's probably more interesting to say,</a> <a data-t="956">does deep learning provide improvements on the techniques</a> <a data-t="960">we have for our traditional domains?</a></p>

<h3>How deep learning models are trained</h3>

<p><a data-t="1001">So I want to talk a little bit about the mechanism</a> <a data-t="1003">of how these models are trained, what happens,</a> <a data-t="1005">and try to convince you that this is actually</a> <a data-t="1007">a pretty simple and straightforward mechanism.</a> <a data-t="1009">And it's actually kind of surprising that it's</a> <a data-t="1011">able to solve the kind of problems that it solves.</a> <a data-t="1014">So I'll start with a little bit of the basics of how machine learning</a> <a data-t="1017">algorithms work, and then give you an example</a> <a data-t="1019">of kind of how the training loop for a deep learning model works.</a></p>

<p><a data-t="1023">So just to define some terms, the way machine learning algorithms typically</a> <a data-t="1027">work is that you start out with a bunch of data.</a> <a data-t="1030">You have x, and you have a known y.</a> <a data-t="1032">And you basically just feed batches of that data into the model.</a> <a data-t="1035">And the model basically incrementally improves its coefficients</a> <a data-t="1040">by examining the prediction, saying how close was the prediction</a> <a data-t="1044">to the actual value, and then adjusting the weights.</a> <a data-t="1047">And the training process is a sort of iterative training process</a> <a data-t="1051">that takes advantage of a loss function to evaluate the model</a> <a data-t="1054">and then tweak it over time.</a> <a data-t="1055">That's kind of how they work.</a></p>

<p><a data-t="1058">There's significant kind of differences in orientation</a> <a data-t="1060">between statistical modeling and machine learning.</a> <a data-t="1062">I'm not going to go into a lot of depth about that.</a> <a data-t="1064">I have some links here for you to take a look at.</a> <a data-t="1066">But I think one that you'll notice right away</a> <a data-t="1069">is that oftentimes statistics is focused on explanation and understanding.</a> <a data-t="1073">It's focused on kind of inferring the process by which data is generated.</a> <a data-t="1077">And machine learning really, in a lot of cases,</a> <a data-t="1079">is exclusively concerned with efficacy of prediction.</a> <a data-t="1082">Can we predict things?</a> <a data-t="1082">We don't need to explain or understand the phenomena.</a> <a data-t="1085">We just want to predict it.</a> <a data-t="1086">So as you're going to see, these deep learning models</a> <a data-t="1088">are total black box models.</a> <a data-t="1089">They do nothing to help you explain or understand phenomena.</a> <a data-t="1093">But they work well for prediction.</a> <a data-t="1095">So that's kind of where that orientation comes from.</a></p>

<h3>Keras layers, compilation, and the cheat sheet</h3>

<p><a data-t="2341">So layers is kind of the core construct in Keras.</a> <a data-t="2345">And there's actually 65 different layers available,</a> <a data-t="2348">and you can create your own layers.</a> <a data-t="2350">This is just a sampling of some of them.</a> <a data-t="2352">I'm going to talk categorically about some</a> <a data-t="2353">of the types of layers that there are.</a></p>

<p><a data-t="2356">There's dense layers, which are kind</a> <a data-t="2358">of the staple of neural networks.</a> <a data-t="2360">These work the same way that traditional neural networks that</a> <a data-t="2363">were written about and used in the 70s work.</a> <a data-t="2367">And they're kind of a staple of every deep learning model.</a> <a data-t="2371">Usually, if you're using more sophisticated layers</a> <a data-t="2373">at the end of the model, you'll have these dense layers.</a> <a data-t="2376">And these dense layers are really just</a> <a data-t="2377">a bunch of weights and biases that</a> <a data-t="2379">are applied and cascade through other dense layers.</a></p>

<p><a data-t="2384">Convolutional layers are used for computer vision,</a> <a data-t="2388">most commonly.</a> <a data-t="2389">And they're basically trying to find spatial features.</a> <a data-t="2394">And they're trying to find spatial features that,</a> <a data-t="2396">when they learn, like, for example, what an edge is</a> <a data-t="2398">or what an eyeball is, that knowledge</a> <a data-t="2402">is actually transferable to other parts of the image.</a> <a data-t="2405">So if I see an eye in a certain quadrant of the image,</a> <a data-t="2407">and then I see later on an eye in another quadrant,</a> <a data-t="2410">I can still recognize that as an eye.</a> <a data-t="2412">So the reason it's convolutional is</a> <a data-t="2413">we're building up these filters that recognize patterns.</a> <a data-t="2416">And then we're convolving, sliding the filter</a> <a data-t="2418">across the entire image.</a> <a data-t="2421">And you can see an example of that here.</a> <a data-t="2423">So again, there's much better explanations</a> <a data-t="2426">for how this works.</a> <a data-t="2427">But you can think of convolutional layers</a> <a data-t="2429">as really good for image processing,</a> <a data-t="2430">spatial dependencies, that sort of thing.</a></p>

<p><a data-t="2433">Recurrent layers are basically layers</a> <a data-t="2436">that have some memory or state.</a> <a data-t="2438">And so if you're dealing with sequence data,</a> <a data-t="2439">like time series data or text,</a> <a data-t="2442">where it matters not only what I'm seeing now,</a> <a data-t="2444">but what I've seen in the past,</a> <a data-t="2446">recurrent layers are able to maintain state.</a> <a data-t="2448">So they're oftentimes used</a> <a data-t="2449">in these sequence-oriented applications.</a></p>

<p><a data-t="2451">And then embedding layers,</a> <a data-t="2453">for those of you who do natural language processing,</a> <a data-t="2455">is a way of vectorizing text.</a> <a data-t="2458">So one way to vectorize text would be to say,</a> <a data-t="2461">I've got an instance of the word cat,</a> <a data-t="2463">an instance of the word dog, and they're just classes.</a> <a data-t="2466">It's just cat versus dog.</a> <a data-t="2467">But another way would be,</a> <a data-t="2468">I've got a vector that represents</a> <a data-t="2470">semantic relationships between words.</a> <a data-t="2472">So in one of the dimensions of that,</a> <a data-t="2475">one of the axes of that vector,</a> <a data-t="2477">I've got a thing that says,</a> <a data-t="2478">oh, cat and dog are both animals.</a> <a data-t="2480">So embedding layers do this kind of vectorization.</a> <a data-t="2485">And you can actually learn the embedding jointly</a> <a data-t="2488">with building the model,</a> <a data-t="2490">or you can load a pre-trained word embedding</a> <a data-t="2492">that we conventionally use, like word2vec.</a> <a data-t="2494">You can load one of those embeddings</a> <a data-t="2495">into an embedding layer.</a> <a data-t="2497">So there's just a few of the layer types,</a> <a data-t="2499">but again, there's 65 layers.</a> <a data-t="2500">And a lot of what doing deep learning is</a> <a data-t="2503">is trying to figure out what is the right composition</a> <a data-t="2505">of those layers and behavior of those layers</a> <a data-t="2506">to get a model that works well.</a></p>

<p><a data-t="2509">So in Keras, once we define our layers,</a> <a data-t="2512">we compile the model, and what is that really?</a> <a data-t="2515">The compilation of a model is really converting the layers</a> <a data-t="2517">into a TensorFlow graph,</a> <a data-t="2518">and then applying the loss function and optimizer to those.</a> <a data-t="2522">That's what compile, the compile step really does.</a></p>

<p><a data-t="2526">There are a wide variety of loss functions</a> <a data-t="2528">available in Keras,</a> <a data-t="2530">and you can actually write your own loss functions.</a> <a data-t="2531">So depending on what you're doing,</a> <a data-t="2533">you'll use maybe a custom loss</a> <a data-t="2534">or maybe one of the built-in losses</a> <a data-t="2535">or more than one of the built-in losses.</a> <a data-t="2538">There are many optimizers that are built in.</a> <a data-t="2540">Again, these optimizers don't require</a> <a data-t="2542">that all the memory is in RAM.</a> <a data-t="2544">There are many metrics built in,</a> <a data-t="2546">and you can write your own metrics.</a> <a data-t="2548">So these are ways of assessing how the model is training,</a> <a data-t="2550">how it's behaving, how well it's doing.</a></p>

<h3>Explainability of predictions</h3>

<p><a data-t="2782">Couple examples about addressing explainability,</a> <a data-t="2785">because again, while 138 million parameter model,</a> <a data-t="2789">looking at it doesn't tell you anything about the phenomena,</a> <a data-t="2792">it is actually possible oftentimes to understand</a> <a data-t="2795">why a given prediction was made by a neural network.</a> <a data-t="2798">Here's an example of,</a> <a data-t="2801">we're classifying images,</a> <a data-t="2802">and we've predicted that this image is an African elephant,</a> <a data-t="2806">and actually by inspecting the gradients</a> <a data-t="2808">of the intermediate layers,</a> <a data-t="2809">it's possible to pull out a heat map that says,</a> <a data-t="2812">these are the parts of the image</a> <a data-t="2814">that most caused us to do this classification.</a></p>

<p><a data-t="2817">So then we juxtapose the heat map over the original image,</a> <a data-t="2820">and we actually see, this is why the model,</a> <a data-t="2822">these are the things that contributed to the model</a> <a data-t="2824">saying that this was an African elephant.</a> <a data-t="2826">And then similarly LIME,</a> <a data-t="2828">which allows you to take an individual prediction</a> <a data-t="2830">and say what features contributed to that prediction.</a></p>

<p><a data-t="2834">So there is work going on in explainability of predictions,</a> <a data-t="2838">it's not the same thing as I look at the model</a> <a data-t="2840">and it explains the phenomena,</a> <a data-t="2841">but a lot of these models are gonna be used</a> <a data-t="2844">if they're being used for things like patient care</a> <a data-t="2845">or making recommendations about surgical procedures</a> <a data-t="2848">or approving or denying loans,</a> <a data-t="2851">they have to be explainable.</a> <a data-t="2852">We have to be able to say,</a> <a data-t="2853">we have a machine learning algorithm,</a> <a data-t="2855">but this is why the machine learning algorithm</a> <a data-t="2857">is coming out the way it is.</a></p>

<h3>Deep learning frontiers and experimentation</h3>

<p><a data-t="2860">So kind of coming back to this idea of frontiers,</a> <a data-t="2865">many fields have a deep learning frontier</a> <a data-t="2867">that is not yet reached or even well approached,</a> <a data-t="2870">and in most of these cases,</a> <a data-t="2873">the traditional statistical modeling</a> <a data-t="2874">and machine learning methods are cheaper and more accurate.</a> <a data-t="2877">So it's really pretty,</a> <a data-t="2879">once you get out of computer vision</a> <a data-t="2880">and language translation,</a> <a data-t="2883">a lot of this stuff is in the research stage,</a> <a data-t="2885">it's in the speculative stage.</a></p>

<p><a data-t="2887">And I think there's different approaches</a> <a data-t="2888">you could take to that.</a> <a data-t="2889">Right now, creating an image classifier</a> <a data-t="2891">that has a super high accuracy is just completely trivial.</a> <a data-t="2894">So that field, that frontier is explored</a> <a data-t="2896">and understood and applicable.</a></p>

<p><a data-t="2899">But in other cases, the frontier is far away.</a> <a data-t="2903">So you could wait and see, wait till,</a> <a data-t="2905">okay, I do this type of time series forecasting,</a> <a data-t="2907">it's not proven that deep learning helps me,</a> <a data-t="2909">I'll just wait and see until it is proven</a> <a data-t="2911">and then I'll apply it then.</a> <a data-t="2912">Another approach could be to try to see</a> <a data-t="2914">what contemporary research is doing,</a> <a data-t="2916">see both formal research</a> <a data-t="2918">and what people are publishing on the web,</a> <a data-t="2920">and evaluate that and try that with your data</a> <a data-t="2923">and your work and see if it improves things.</a> <a data-t="2925">And yet another approach is to actually try to,</a> <a data-t="2927">in your field of endeavor, try to approach the frontier,</a> <a data-t="2930">try to see if you can find novel applications</a> <a data-t="2932">for deep neural nets.</a></p>

<p><a data-t="2934">So all of this requires,</a> <a data-t="2937">it's great to show examples that do interesting things,</a> <a data-t="2940">but it does require a lot of work and time</a> <a data-t="2942">and patience and iteration to get these models to work well.</a> <a data-t="2945">So in practice, there's a huge amount of experimentation</a> <a data-t="2948">that's done with model architecture, with hyperparameters.</a> <a data-t="2951">And what happens is people gain better intuition</a> <a data-t="2955">about what sorts of models and layers</a> <a data-t="2958">and other things work well</a> <a data-t="2960">for the class of data problems that they have.</a></p>

<p><a data-t="2963">So it tends to require a lot of iteration,</a> <a data-t="2965">it tends to require a lot of compute power,</a> <a data-t="2967">and it sort of tends to require some related tools</a> <a data-t="2969">to help you kind of streamline your workflow</a> <a data-t="2971">and make the most of the compute power you have.</a> <a data-t="2973">And that's kind of the next piece that I want to talk about</a> <a data-t="2976">is the tools that we've built to help you with the process.</a> <a data-t="2979">Kind of first and foremost is using GPUs.</a></p>

<h3>Using GPUs and cloud resources</h3>

<p><a data-t="2984">Some deep learning models work great on CPUs.</a> <a data-t="2987">Ones that use convolution or recurrent neural networks</a> <a data-t="2991">tend to be very slow on CPUs.</a> <a data-t="2993">So if you go to our TensorFlow for R website,</a> <a data-t="2997">there's a bunch of resources</a> <a data-t="2998">about different ways you can use GPUs.</a> <a data-t="3000">One is if you have a high-end NVIDIA graphics card,</a> <a data-t="3004">you can use a GPU on your local system.</a> <a data-t="3007">There's cloud services that let you do batch jobs</a> <a data-t="3010">that use GPUs.</a> <a data-t="3012">You can set up a cloud server with RStudio Server</a> <a data-t="3014">on Google Compute or Amazon or Azure.</a> <a data-t="3017">And there's even ways to actually have</a> <a data-t="3019">a virtual cloud Linux desktop that has a GPU.</a> <a data-t="3021">So all that's covered on our GPU page.</a> <a data-t="3023">I won't talk about that further,</a> <a data-t="3024">but it's definitely something to look into</a> <a data-t="3027">if you want to explore.</a></p>

<h3>The <a href="/software/tfruns/">tfruns</a> package</h3>

<p><a data-t="3030">We have another package called tfruns,</a> <a data-t="3031">stands for TensorFlow runs.</a> <a data-t="3033">And the idea here is that because</a> <a data-t="3036">a huge amount of experimentation</a> <a data-t="3038">is required with deep learning models,</a> <a data-t="3039">you're going to run a ton of training jobs.</a> <a data-t="3042">Instead of using the source function to run those jobs,</a> <a data-t="3044">you use a function called training run.</a> <a data-t="3046">And what training run does is it records</a> <a data-t="3048">everything about that job.</a> <a data-t="3049">The source code, the output,</a> <a data-t="3051">the performance of the model,</a> <a data-t="3053">the hyperparameters you use for the model.</a> <a data-t="3054">And then you basically have a data frame</a> <a data-t="3056">at the end for all the model runs that you've ever done.</a> <a data-t="3059">And then you can compute on that data frame</a> <a data-t="3061">to try to understand better what's working well</a> <a data-t="3063">and not working well.</a></p>

<p><a data-t="3065">It also gives you reports on each runs</a> <a data-t="3066">that summarize, again, the code, the model,</a> <a data-t="3069">the metrics, the performance of the model.</a> <a data-t="3071">So every single time you do a training run,</a> <a data-t="3073">one of these reports is generated.</a> <a data-t="3075">And then you can compare runs.</a> <a data-t="3076">So if you find, okay, I've examined my data frame.</a> <a data-t="3079">I found that these are my best two performing models.</a> <a data-t="3082">What was different about them?</a> <a data-t="3083">And you can see in this case,</a> <a data-t="3084">it's showing a source code diff saying</a> <a data-t="3086">I changed two things in the source code.</a> <a data-t="3087">And that accounts for that difference in performance.</a></p>

<p><a data-t="3092">And there's another piece called flags,</a> <a data-t="3095">which basically says if there's important aspects</a> <a data-t="3097">of my model, it's good to externalize those,</a> <a data-t="3100">get them out of my source code</a> <a data-t="3101">so that I can kind of pass these flags</a> <a data-t="3103">to my script as a parameter.</a> <a data-t="3105">So you can see I'm defining a set of flags here.</a> <a data-t="3108">And then I'm using the flags when I define a layer.</a> <a data-t="3111">And then when I train the model,</a> <a data-t="3112">I'm passing one of the flags.</a> <a data-t="3114">They're basically kind of command line parameters</a> <a data-t="3116">for your script that let you easily vary things.</a></p>

<p><a data-t="3119">And then that in turn enables this construct</a> <a data-t="3122">called a tuning run that says,</a> <a data-t="3124">okay, I've got two types of dropout.</a> <a data-t="3127">In this case, I'm gonna vary dropout from 0.2 to 0.4.</a> <a data-t="3132">And I want you to try every combination</a> <a data-t="3134">of those two hyperparameters</a> <a data-t="3137">and then tell me what the best model is.</a> <a data-t="3139">And if the number of combinations gets very, very large,</a> <a data-t="3141">you know, into the thousands,</a> <a data-t="3143">then you can actually sample from that</a> <a data-t="3144">and only run 50 training jobs</a> <a data-t="3149">rather than thousands of them</a> <a data-t="3150">to try to evaluate what the best model is.</a> <a data-t="3153">But these sort of tools end up being critical</a> <a data-t="3155">to getting deep learning models that perform well</a> <a data-t="3157">because you have to try so many different things.</a></p>

<h3>Cloud ML for training and hyperparameter tuning</h3>

<p><a data-t="3161">The Cloud ML package is our interface to Google Cloud ML.</a> <a data-t="3165">And Google Cloud ML basically lets you train models,</a> <a data-t="3168">sort of, you sort of submit batch jobs to Cloud ML</a> <a data-t="3171">and then the model trains.</a> <a data-t="3172">And what's really cool about it is that they have GPUs</a> <a data-t="3175">and they actually have some really, really fast GPUs</a> <a data-t="3177">and even machines that have multiple fast GPUs available.</a> <a data-t="3182">And they also have a service for doing</a> <a data-t="3183">this hyperparameter tuning that I just talked about.</a> <a data-t="3186">So the idea is you want to work</a> <a data-t="3188">from the comfort of your laptop</a> <a data-t="3189">with smaller down-sampled data.</a> <a data-t="3191">And then when you want to actually do your training,</a> <a data-t="3193">that's going to take three hours.</a> <a data-t="3195">You submit it to Cloud ML and then it takes 20 minutes,</a> <a data-t="3197">hopefully, instead of three hours.</a></p>

<p><a data-t="3200">Similar to Training Run,</a> <a data-t="3201">there's a function called Cloud ML Train.</a> <a data-t="3203">And when you give an R script to Cloud ML Train,</a> <a data-t="3205">it'll actually upload the contents</a> <a data-t="3207">of the working directory to Cloud ML.</a> <a data-t="3208">It'll actually figure out what packages you're using</a> <a data-t="3211">and make sure those packages are installed</a> <a data-t="3213">on the Cloud ML server.</a> <a data-t="3216">And then when I do this,</a> <a data-t="3217">I can actually specify the kind of hardware I want to use.</a> <a data-t="3218">So in this case, I'm saying use a standard GPU.</a> <a data-t="3221">In this case, I'm saying use like super pumped up,</a> <a data-t="3225">latest and greatest NVIDIA Tesla GPU.</a></p>

<p><a data-t="3229">And then you kind of similarly,</a> <a data-t="3231">once you do a training job, you can collect the results.</a> <a data-t="3233">You can get all the files that were generated.</a> <a data-t="3234">You can get a report about how it did.</a> <a data-t="3237">You can see all your jobs in a data frame.</a></p>

<p><a data-t="3240">And then once, if you're using these flags</a> <a data-t="3243">that I talked about,</a> <a data-t="3244">you can actually do hyper parameter tuning.</a> <a data-t="3246">So in this case, I've defined my flags</a> <a data-t="3248">and I've used them in kind of composing my model.</a> <a data-t="3251">And I can write a YAML file that I give to Cloud ML</a> <a data-t="3254">and I can say, here's the parameters.</a> <a data-t="3256">Here's how I want to vary them.</a> <a data-t="3258">And here's the metric that I'm trying to optimize for.</a> <a data-t="3262">In this case, it's validation accuracy.</a> <a data-t="3264">And here's how many trials I want to run.</a> <a data-t="3266">So this is a way to search over huge spaces of models.</a> <a data-t="3269">And it's all done remotely in the cloud.</a> <a data-t="3272">And you're kind of just only charged</a> <a data-t="3274">for the compute that you use in the execution of those jobs.</a></p>

<p><a data-t="3279">So when the job is done, you get a summary of all the jobs,</a> <a data-t="3282">what the flags were, and what the accuracy was.</a> <a data-t="3287">And so you can figure out what architecture</a> <a data-t="3290">and hyper parameters work best for your model.</a></p>
