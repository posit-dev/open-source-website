<h3>The Prime Directive</h3>

<p><a data-t="160">The idea at the heart of everything we're talking about today is from a gentleman by the name of John Chambers.</a> <a data-t="164">He's one of the most important figures in the history of statistical computing.</a> <a data-t="168">He created the S programming language at AT&T Bell Labs, which was implemented as R in the 90s.</a> <a data-t="174">He taught at Stanford, and in his book in 2008, he articulated what he called the Prime Directive.</a></p>

<p><a data-t="183">The Prime Directive is this. Software for data analysis must be trustworthy, and it must be shown to be trustworthy.</a> <a data-t="190">If you read that carefully, it's not enough for your analysis to be correct.</a> <a data-t="193">The correctness must be demonstrable. The computation must be transparent.</a> <a data-t="197">Anyone who receives the results of your work has limited opportunity to verify the results of direct observation.</a> <a data-t="204">They have no choice but to trust the analysis, and by extension, the software that produced it.</a> <a data-t="209">That places an enormous obligation on all of us.</a></p>

<blockquote><a data-t="183">The Prime Directive is this. Software for data analysis must be trustworthy, and it must be shown to be trustworthy.</a></blockquote>

<p><a data-t="212">This is why we've always believed in code-first data science.</a> <a data-t="216">Code is the mechanism by which you satisfy the Prime Directive.</a> <a data-t="219">Code can be read, code can be reviewed, code can be tested, reproduced, and audited.</a> <a data-t="225">A low-code or point-and-clicks interface cannot make the same promise unless every operation it performs is expressible as code that others can read, review, and reproduce.</a></p>

<p><a data-t="236">This is the exact lens through which we evaluate every AI claim.</a> <a data-t="240">Not, is it impressive, or is it fast, but can it be trusted, and can that trust be proven?</a></p>

<p><a data-t="248">So why code-first?</a> <a data-t="251">The Prime Directive is not just a philosophy. In a GXP environment, it is a practical necessity.</a> <a data-t="257">When a regulator asks you to explain your analysis, the code and your SOPs are your answer.</a> <a data-t="264">When an auditor needs to verify that the method was applied correctly, the code is your evidence.</a> <a data-t="269">When a colleague needs to reproduce your results six months later, the code is your insurance.</a></p>

<p><a data-t="275">This is why we have invested in making code-first data science more powerful, more accessible, and more reproducible.</a> <a data-t="281">Not because it's trendy, but because it is the only architecture that makes the Prime Directive achievable in a regulated environment.</a> <a data-t="287">Keep this principle in your mind as we go through the rest of the talk, because the question of whether AI can be used responsibly in your work comes down to one thing.</a> <a data-t="295">Can it be made to satisfy the Prime Directive?</a></p>

<h3>Five common objections</h3>

<p><a data-t="917">Over the past two years, we've had conversations with dozens of pharmaceutical data science leaders</a> <a data-t="921">across North America, Europe, and Japan.</a> <a data-t="923">The concerns are remarkably consistent.</a> <a data-t="926">Five objections come up in almost every conversation, whether it's in pharma, healthcare,</a> <a data-t="931">or even governmental agency.</a> <a data-t="933">So let us tackle them one by one.</a></p>

<h3>Objection one: we cannot validate AI-generated code</h3>

<p><a data-t="943">We cannot validate AI-generated code.</a> <a data-t="945">This is the most common objection.</a> <a data-t="948">It spawns several smaller questions, including can we trust code that a machine wrote?</a> <a data-t="953">And the answer is not without some means of confirming its correctness.</a> <a data-t="956">There are important best practices that the industry is still learning and codifying.</a></p>

<p><a data-t="961">Still, the approach we are committed to is one where every piece of an analysis is written as code</a> <a data-t="965">and therefore is inspectable.</a></p>

<p><a data-t="969">Another question is who is responsible when it is wrong?</a> <a data-t="972">And the answer is ultimately you are.</a> <a data-t="975">You can't tell your management team that the AI said that this was the right answer.</a> <a data-t="979">For some organizations, you have seen the practice of double programming.</a> <a data-t="984">Ultimately, the goal is to make sure that two independent individuals</a> <a data-t="987">will get the same results given the same inputs.</a> <a data-t="990">You can simulate that type of process with AI.</a> <a data-t="992">Most importantly, you need to make sure you understand the work produced</a> <a data-t="996">and ensure that it is well documented and tested.</a> <a data-t="998">The readability and succinctness of R plus the tidyverse</a> <a data-t="1001">should be particularly helpful for organizations</a> <a data-t="1004">as a human's ability to review massive amounts of code is the next bottleneck.</a></p>

<p><a data-t="1009">Can an auditor verify the process?</a> <a data-t="1012">And the answer is absolutely, because the output of the work is code</a> <a data-t="1015">that is reproducible, inspectable, and testable.</a> <a data-t="1018">There should be no reason why an auditor would have an issue with it.</a> <a data-t="1022">The fact that an AI wrote that code is irrelevant.</a> <a data-t="1025">What is relevant is that the testing of the code followed your SOPs.</a></p>

<p><a data-t="1029">The GXP anxiety is very real.</a> <a data-t="1032">AI systems are probabilistic.</a> <a data-t="1034">They can generate code that looks correct when it may not be.</a> <a data-t="1037">They can miss edge cases.</a> <a data-t="1038">They can be confidently wrong.</a> <a data-t="1040">But guess what?</a> <a data-t="1042">So can humans.</a></p>

<p><a data-t="1045">But here's what we have learned.</a> <a data-t="1047">The answer is not to keep humans out of the loop as a safety check at the end.</a> <a data-t="1050">The answer is to design the human into the loop</a> <a data-t="1053">as an architectural requirement throughout.</a> <a data-t="1056">The statistician or programmer is not the last line of defense against AI errors.</a> <a data-t="1060">They are the pilot.</a> <a data-t="1062">AI is a copilot that can do a great deal of useful work.</a> <a data-t="1066">But the pilot always has a hand on the controls,</a> <a data-t="1069">always understands what's going, what is happening,</a> <a data-t="1071">and always bears responsibility for the outcome.</a></p>

<blockquote><a data-t="1056">The statistician or programmer is not the last line of defense against AI errors.</a> <a data-t="1060">They are the pilot.</a> <a data-t="1062">AI is a copilot that can do a great deal of useful work.</a> <a data-t="1066">But the pilot always has a hand on the controls,</a> <a data-t="1069">always understands what's going, what is happening,</a> <a data-t="1071">and always bears responsibility for the outcome.</a></blockquote>

<p><a data-t="1074">Code First makes this possible.</a> <a data-t="1076">When AI outputs our code,</a> <a data-t="1079">our readable, executable, and version-controlled code,</a> <a data-t="1082">the human expert can review, understand, test, and validate the output</a> <a data-t="1085">before it becomes part of the permanent record.</a> <a data-t="1088">That is the prime directive applied to AI-assisted work.</a></p>

<h3>Objection two: AI will replace our statisticians</h3>

<p><a data-t="1094">The second objection is AI will replace our statisticians.</a> <a data-t="1098">I mentioned our company-wide workweek in the dead of winter in Minneapolis</a> <a data-t="1101">in 2024 and 2025.</a> <a data-t="1103">This year, we held it in Monterey, California,</a> <a data-t="1105">to give us all an opportunity to see each other outdoors.</a> <a data-t="1108">See, I'm not entirely heartless.</a></p>

<p><a data-t="1111">My keynote focused on the traits and mindsets that we all need</a> <a data-t="1114">in order to navigate the changes stemming from AI.</a> <a data-t="1117">Our team's fears echoed those of some of our customers</a> <a data-t="1120">who wonder what would become of them if 50, 70, or even 100% of their day-to-day work</a> <a data-t="1125">was no longer relevant in this new world.</a> <a data-t="1128">The truth is, none of us can really predict which jobs will disappear altogether.</a> <a data-t="1133">The introduction of cars in the early 1900s eliminated many roles</a> <a data-t="1138">and radically curtailed the number of other jobs.</a> <a data-t="1141">For today, I believe it is most helpful to focus on jobs</a> <a data-t="1145">that will continue to exist, but whose means of doing the work</a> <a data-t="1148">are fundamentally changed.</a></p>

<p><a data-t="1150">Let me offer you an analogy.</a> <a data-t="1153">Here's a man in this image.</a> <a data-t="1157">And everybody has identified that this person is a carpenter.</a> <a data-t="1162">Here's another man in this image.</a> <a data-t="1166">And again, they both have the same title,</a> <a data-t="1170">and they both may have the same level of commitment to their craft.</a> <a data-t="1174">But if you're building a deck at your home,</a> <a data-t="1177">one of them will finish the work in three days,</a> <a data-t="1179">and one will take two weeks.</a> <a data-t="1181">Who do you hire?</a> <a data-t="1183">The answer is obvious.</a> <a data-t="1184">We hire the person with the power tools</a> <a data-t="1187">because they've respected our time and resources enough</a> <a data-t="1190">to master the best tools available.</a></p>

<p><a data-t="1192">In a world of power tools,</a> <a data-t="1194">the handsaw is no longer the professional standard.</a> <a data-t="1196">That does not mean that there's no place for the handsaw</a> <a data-t="1199">and the hammer in this new world,</a> <a data-t="1201">but the bulk of the work will be handled by the power tools.</a> <a data-t="1204">The statistician and programmer who uses AI tools</a> <a data-t="1207">to accelerate their work is not a lesser statistician or programmer.</a> <a data-t="1210">They are the statisticians and programmers</a> <a data-t="1212">who finish the job in three days.</a> <a data-t="1214">What AI eliminates is the syntax tasks,</a> <a data-t="1217">the hours spent on translation errors,</a> <a data-t="1220">boilerplate code, and copying and pasting.</a> <a data-t="1222">What it frees is judgment, domain expertise, and scientific insight.</a> <a data-t="1226">Those are precisely the things that took decades to develop</a> <a data-t="1229">and that no AI currently replicates.</a></p>

<p><a data-t="1232">I know that some in this room are likely saying,</a> <a data-t="1234">but what good is speed if we fail an audit?</a> <a data-t="1237">And that is a fair concern.</a> <a data-t="1239">Speed doesn't have to mean less attention or lower accuracy.</a> <a data-t="1243">Just as cutting a piece of wood with a power saw</a> <a data-t="1245">doesn't have to be less accurate than using a handsaw.</a> <a data-t="1248">The domain knowledge you have built over your career,</a> <a data-t="1251">how clinical trials work,</a> <a data-t="1253">what the regulatory standards require,</a> <a data-t="1255">what the science demands is most valuable in this new era, not less.</a> <a data-t="1259">The AI amplifies that knowledge.</a> <a data-t="1261">It doesn't replace it.</a></p>

<p><a data-t="1263">I had thought that the carpenter analogy was useful in March</a> <a data-t="1266">and apparently terrifying to some of our employees,</a> <a data-t="1268">as I recently learned.</a> <a data-t="1270">A few weeks later, I realized that it is incomplete</a> <a data-t="1273">and falls into the common trap</a> <a data-t="1276">when we think about the risk with AI.</a> <a data-t="1278">And I want to show you why with an example from your own world.</a> <a data-t="1281">Think about the process of generating tables,</a> <a data-t="1283">listings, and figures at the end of a trial phase.</a> <a data-t="1286">Now ask yourself, what if the question isn't,</a> <a data-t="1288">how do I generate TLS faster?</a> <a data-t="1290">But why are we waiting until the end of the trial</a> <a data-t="1292">to look at safety signals at all?</a></p>

<p><a data-t="1295">That question isn't about tools and speed.</a> <a data-t="1297">It's about the system and the constraints in the system.</a> <a data-t="1300">We'll come back to that question,</a> <a data-t="1302">but hold it for now because it is the question</a> <a data-t="1304">that separates those who think of themselves</a> <a data-t="1306">as carpenters with better tools</a> <a data-t="1308">and those who reimagine themselves</a> <a data-t="1310">as the person who designs and builds the whole outdoor space,</a> <a data-t="1314">the deck, the wiring, the grilling station.</a></p>

<h3>Objection three: we can't trust the models with our data</h3>

<p><a data-t="1319">Objection three.</a> <a data-t="1321">We can't trust the models with our data.</a> <a data-t="1325">This is a governance question, not an AI question,</a> <a data-t="1327">and it has a governance answer.</a> <a data-t="1329">I've had at least a half a dozen conversations</a> <a data-t="1331">over the past few months about this topic.</a> <a data-t="1334">The concern is legitimate.</a> <a data-t="1336">Patient data, trial data, proprietary compound information,</a> <a data-t="1340">historically, there would be no scenario</a> <a data-t="1342">in which that data could leave your systems.</a> <a data-t="1345">For some companies, that requirement is still true,</a> <a data-t="1348">and local models may well be the right answer here</a> <a data-t="1351">if your organization is not using any cloud capabilities.</a></p>

<p><a data-t="1356">The good news is that local models</a> <a data-t="1359">have had a genuine step change in performance this spring,</a> <a data-t="1362">particularly Google's Gemma 4 and Alibaba's Quen 3.5</a> <a data-t="1366">and newer models, bringing them much closer</a> <a data-t="1368">to the mainstream usefulness for this class of work.</a> <a data-t="1372">However, many more companies have already embraced the cloud</a> <a data-t="1375">or used some of the top data platforms.</a> <a data-t="1378">There's another path forward that will allow you</a> <a data-t="1380">to access these models safely.</a></p>

<p><a data-t="1383">While the models themselves are stateless</a> <a data-t="1386">and your prompts and data are not stored by the model,</a> <a data-t="1389">the providers all have the ability,</a> <a data-t="1391">and in almost all cases, the legal requirement</a> <a data-t="1394">to store the prompts and responses</a> <a data-t="1396">for safety or abuse reasons.</a> <a data-t="1399">There is a concept called zero data retention,</a> <a data-t="1401">known in the industry as ZDR,</a> <a data-t="1403">which is provided by a few of the cloud providers</a> <a data-t="1408">and data platforms today,</a> <a data-t="1410">but it is not uniformly available across all the platforms.</a> <a data-t="1413">ZDR is meant to ensure that the provider</a> <a data-t="1415">is not permanently storing the prompts</a> <a data-t="1417">in addition to the usual commitments</a> <a data-t="1419">of not using the data for any training.</a></p>

<p><a data-t="1421">It would be fair to take issue</a> <a data-t="1422">with the current definition of zero</a> <a data-t="1424">since providers like Anthropic</a> <a data-t="1426">will retain enough summary and metadata information</a> <a data-t="1428">to be able to ensure user safety classifier results</a> <a data-t="1432">and enforce their usage policy,</a> <a data-t="1434">even in a platform that supports ZDR.</a> <a data-t="1437">We started out with AWS Bedrock</a> <a data-t="1439">for our access to cloud code,</a> <a data-t="1441">and we're comfortable with the level of agreements</a> <a data-t="1443">we have with AWS,</a> <a data-t="1446">even though they are retaining the prompts</a> <a data-t="1447">and responses for some time.</a> <a data-t="1449">The agreement we put together in place with Anthropic</a> <a data-t="1452">does allow us to configure ZDR for our usage,</a> <a data-t="1455">although the data retention is configurable</a> <a data-t="1457">by our IT and governance teams.</a></p>

<p><a data-t="1460">IT and governance teams will push back</a> <a data-t="1462">on the use of AI because of the concerns</a> <a data-t="1464">that data is moving outside the boundaries</a> <a data-t="1466">that they have defined for it.</a> <a data-t="1468">Our counter argument is that for most</a> <a data-t="1470">of the customers we have met,</a> <a data-t="1471">they are already trusting AWS, Azure, GCP,</a> <a data-t="1476">Databricks, Snowflake, and Palantir</a> <a data-t="1478">with the security of their systems and their data,</a> <a data-t="1480">and they likely already have the legal agreements</a> <a data-t="1483">that would protect them.</a> <a data-t="1485">There is no world we see where your team</a> <a data-t="1487">is better off without secure, approved access to AI tools.</a> <a data-t="1491">You will be using hand tools</a> <a data-t="1492">to compete against people with power tools.</a> <a data-t="1494">This is not a winnable game in the long term.</a></p>

<p><a data-t="1497">Instead, our approach has been to build</a> <a data-t="1499">the right level of scaffolding and guardrails</a> <a data-t="1501">that organizations will need to allow</a> <a data-t="1503">their teams to truly flourish.</a> <a data-t="1506">The foundational pieces are available</a> <a data-t="1507">at the infrastructure level.</a> <a data-t="1509">We're moving through the backlog quickly</a> <a data-t="1510">to add the guardrails that our conversations</a> <a data-t="1512">with all of you have highlighted.</a> <a data-t="1515">The good news is that we are able</a> <a data-t="1516">to go faster than ever,</a> <a data-t="1518">which is both frightening and exhilarating.</a></p>

<h3>Objection four: we don't know which model to trust</h3>

<p><a data-t="1523">Objection four.</a> <a data-t="1524">We don't know which model to trust.</a> <a data-t="1527">This is a very real concern.</a> <a data-t="1528">However, the answer is not to wait</a> <a data-t="1530">for an evaluation of a given model</a> <a data-t="1532">before you give your teams access to AI.</a> <a data-t="1534">The reality is that models are changing</a> <a data-t="1536">at breakneck speed and leapfrog each other regularly.</a> <a data-t="1540">The organization's focus should be on building systems</a> <a data-t="1543">that enable you to switch between models.</a> <a data-t="1546">We have some customers who can only run</a> <a data-t="1548">on Azure and use Copilot,</a> <a data-t="1550">and others may be locked into Anthropic or Gemini.</a> <a data-t="1553">We believe that organizations will need the flexibility</a> <a data-t="1555">to seamlessly switch between models,</a> <a data-t="1558">possibly even for different tasks or use cases.</a> <a data-t="1561">What was state-of-the-art in mid-November</a> <a data-t="1563">had changed by the end of the month.</a></p>

<p><a data-t="1566">Like the validation process,</a> <a data-t="1567">which varies widely across organizations,</a> <a data-t="1570">our belief is that we should make it as easy as possible</a> <a data-t="1573">for you to understand how the tools are being used</a> <a data-t="1576">and to assess the quality of the work being produced.</a> <a data-t="1579">Your strategy for AI adoption shouldn't start</a> <a data-t="1581">with ensuring you have a trustworthy model.</a> <a data-t="1584">It should start with accepting</a> <a data-t="1586">that you can never trust any model implicitly.</a></p>

<p><a data-t="1590">The answer is to shift the validation target.</a> <a data-t="1592">What you validate is the environment,</a> <a data-t="1594">the governed system within which the output of the AI operates,</a> <a data-t="1598">the reproducible, auditable infrastructure,</a> <a data-t="1601">the human review process,</a> <a data-t="1603">the code-first output standard,</a> <a data-t="1605">the version control and traceability</a> <a data-t="1607">that make every step of the analysis inspectable.</a> <a data-t="1610">A model that operates within a well-governed environment</a> <a data-t="1613">producing code-first outputs</a> <a data-t="1616">that a qualified human reviews and approves</a> <a data-t="1618">satisfies the prime directive,</a> <a data-t="1620">regardless of which underlying model generates it.</a> <a data-t="1623">The architecture is what you validate,</a> <a data-t="1625">not the weights of the model.</a></p>

<blockquote><a data-t="1590">The answer is to shift the validation target.</a> <a data-t="1592">What you validate is the environment,</a> <a data-t="1594">the governed system within which the output of the AI operates,</a> <a data-t="1598">the reproducible, auditable infrastructure,</a> <a data-t="1601">the human review process,</a> <a data-t="1603">the code-first output standard,</a> <a data-t="1605">the version control and traceability</a> <a data-t="1607">that make every step of the analysis inspectable.</a></blockquote>

<h3>Objection five: we are not ready yet</h3>

<p><a data-t="1629">Objection five, we are not ready yet.</a> <a data-t="1633">We are in those very same shoes.</a> <a data-t="1635">In February 2024, if you had asked us, we have said, no.</a> <a data-t="1638">And there's genuine wisdom in that instinct.</a> <a data-t="1641">The risks of moving carelessly in a regulated environment</a> <a data-t="1643">are very real.</a> <a data-t="1645">Posit's own story is instructive here.</a> <a data-t="1647">We were genuinely skeptical to start,</a> <a data-t="1649">but we started experimenting.</a> <a data-t="1650">We found a responsible approach</a> <a data-t="1652">and started introducing AI into our products</a> <a data-t="1654">in a manner that we could defend</a> <a data-t="1656">and with the caveats that we thought were important.</a> <a data-t="1658">The November 2025 releases gave us the confidence</a> <a data-t="1661">to push our organization harder on the adoption curve</a> <a data-t="1664">because our regular engagement with the tools</a> <a data-t="1666">meant we could see exactly how much the models had advanced.</a></p>

<p><a data-t="1670">There's a genuine discomfort that we see</a> <a data-t="1672">when talking to our customers and even our own employees,</a> <a data-t="1675">and they often fall into one of two buckets.</a> <a data-t="1678">In one bucket, the questions are,</a> <a data-t="1680">how do I know that this is safe?</a> <a data-t="1682">And where are the guardrails?</a> <a data-t="1684">And in the second bucket is, what is my role in this new world?</a> <a data-t="1688">We should not confuse the discomfort</a> <a data-t="1690">of doing something differently than we have before</a> <a data-t="1692">with the worry that what we are doing is wrong.</a> <a data-t="1695">There's also a coupling of our professional identity</a> <a data-t="1698">with the tasks we have grown up mastering.</a></p>

<p><a data-t="1702">Within Posit, we are still working through</a> <a data-t="1704">what this means for a variety of roles in the organization</a> <a data-t="1707">in development, QA, sales, marketing, finance, and data science.</a> <a data-t="1712">We have people who have restructured</a> <a data-t="1714">their entire workday around these tools,</a> <a data-t="1716">and others who are deeply uncertain</a> <a data-t="1718">whether that restructuring is responsible at all.</a> <a data-t="1721">Both groups have a point.</a></p>

<p><a data-t="1723">Here's what I can tell you with confidence.</a> <a data-t="1725">Using AI effectively is a skill.</a> <a data-t="1728">It takes time to build, and it is genuinely hard to teach.</a> <a data-t="1732">You have to learn it through experience.</a> <a data-t="1734">Some organizations have been racing up the learning curve</a> <a data-t="1737">for well over a year,</a> <a data-t="1739">and others are still getting their shoes on.</a> <a data-t="1741">That gap is not going to close on its own.</a></p>

<p><a data-t="1744">Running experiments means getting tools</a> <a data-t="1747">into the hands of a small group of people</a> <a data-t="1749">as quickly as possible.</a> <a data-t="1751">The learning only happens through doing.</a> <a data-t="1753">Organizations that spend months</a> <a data-t="1755">eliminating every conceivable risk</a> <a data-t="1757">before allowing anyone to touch AI tools</a> <a data-t="1759">are going to find themselves in trouble.</a> <a data-t="1761">There is no shortcut to learning,</a> <a data-t="1763">and frankly, learning is the new game for us humans.</a></p>

<p><a data-t="1773">So here's the most concrete thing I can offer.</a> <a data-t="1775">Find one bounded problem in your current work</a> <a data-t="1779">and try something.</a> <a data-t="1780">Not because the tools are ready for everything.</a> <a data-t="1782">They are not.</a> <a data-t="1783">But because your judgment about what they are ready for</a> <a data-t="1786">will not improve</a> <a data-t="1787">until you have enough experience to have a judgment.</a> <a data-t="1790">Start narrow.</a> <a data-t="1792">Scope is the variable,</a> <a data-t="1793">not the importance of the problem.</a> <a data-t="1795">And don't wait.</a> <a data-t="1796">The risks of falling behind are too high,</a> <a data-t="1798">not just for your organization,</a> <a data-t="1800">but for you personally.</a></p>

<p><a data-t="1806">We promised you a list of principles.</a> <a data-t="1810">So what does responsible AI</a> <a data-t="1812">in regulated data science actually look like?</a> <a data-t="1815">Based on our own experiences,</a> <a data-t="1817">the customer conversations we've had,</a> <a data-t="1818">and the work we are doing in our products,</a> <a data-t="1820">we have arrived at four principles.</a> <a data-t="1822">They're not the final word.</a> <a data-t="1824">We are still learning,</a> <a data-t="1825">and the field is still evolving.</a> <a data-t="1827">But these are the non-negotiables</a> <a data-t="1829">as we see them today.</a></p>

<h3>The human strand</h3>

<p><a data-t="1899">Which brings us to the second strand,</a> <a data-t="1901">one that I now believe is the harder strand to solve for.</a> <a data-t="1908">Before I move into the second strand,</a> <a data-t="1909">I want to return to the question I left you with</a> <a data-t="1911">a few minutes ago.</a> <a data-t="1913">Who actually wrote the code?</a> <a data-t="1915">On the surface, it sounds like a provenance</a> <a data-t="1917">or a version control question.</a> <a data-t="1920">But the more you sit with it,</a> <a data-t="1921">the more you realize it is asking something deeper.</a> <a data-t="1924">It is asking, what does authorship mean</a> <a data-t="1927">when a machine does the drafting?</a> <a data-t="1929">What does expertise mean when a tool can generate</a> <a data-t="1931">in seconds what used to take hours?</a> <a data-t="1933">What does professional identity mean</a> <a data-t="1935">when the skills you spent a decade mastering</a> <a data-t="1937">are no longer the limiting constraint?</a></p>

<p><a data-t="1940">These are not questions with clean technical answers.</a> <a data-t="1943">They are human questions,</a> <a data-t="1945">and they are exactly where the two strands meet.</a> <a data-t="1948">As you likely saw through the conversation about strand one,</a> <a data-t="1951">the human dimension kept surfacing.</a> <a data-t="1953">In the carpenter analogy, in the TLF question,</a> <a data-t="1956">in the anxiety underneath objection five,</a> <a data-t="1958">these strands are intertwined</a> <a data-t="1960">because you can't really make progress on one</a> <a data-t="1962">without engaging with the other.</a> <a data-t="1965">But solving them requires radically different</a> <a data-t="1967">skill sets and approaches,</a> <a data-t="1968">which is why I wanted to keep them separate</a> <a data-t="1970">long enough to see each one clearly.</a></p>

<p><a data-t="1973">The challenges of adapting to AI are not unique to Pharma.</a> <a data-t="1977">They are universal.</a> <a data-t="1978">And the mindset shifts I'm about to share</a> <a data-t="1980">are the same ones we are working through at Posit every day.</a></p>

<h3>Mindsets for navigating the transition</h3>

<p><a data-t="1986">So what does it actually take to change?</a> <a data-t="1989">I've been thinking for a long time</a> <a data-t="1991">about what it actually takes,</a> <a data-t="1992">not to survive this transition, but to thrive in it.</a> <a data-t="1995">And I have come to believe</a> <a data-t="1996">it comes down to mindsets, not skills.</a> <a data-t="1999">Skills can be learned.</a> <a data-t="2000">Tools can be mastered.</a> <a data-t="2001">But the underlying disposition you bring</a> <a data-t="2003">to an uncertain, fast-moving environment</a> <a data-t="2005">is what determines whether you adapt or freeze.</a></p>

<p><a data-t="2009">I introduced seven mindsets, I believe,</a> <a data-t="2012">that mattered at our work week in March of this year.</a> <a data-t="2015">Today, I want to focus on three</a> <a data-t="2017">that I think speak most directly</a> <a data-t="2019">to the people in this room,</a> <a data-t="2020">to what you do, who you serve,</a> <a data-t="2022">and what you will need to think through.</a></p>

<p><a data-t="2027">To me, it all starts with curiosity,</a> <a data-t="2029">the refusal to accept that's just how it is.</a> <a data-t="2032">There is power in asking,</a> <a data-t="2033">why is something the way it is?</a> <a data-t="2035">Not to be disruptive for its own sake,</a> <a data-t="2037">but because the answer often reveals</a> <a data-t="2039">the assumptions that are built into the system</a> <a data-t="2042">and the constraints that no longer need to exist.</a></p>

<p><a data-t="2045">I planted a question earlier</a> <a data-t="2046">and I said we'd come back to it.</a> <a data-t="2047">Here it is.</a> <a data-t="2048">Why are we waiting until the end of the trial</a> <a data-t="2051">to look at safety signals at all?</a> <a data-t="2053">Think about what the question is really asking.</a> <a data-t="2055">The process of generating tables, listings, and figures</a> <a data-t="2057">at the end of a trial phase exists for reasons.</a> <a data-t="2060">It was designed around constraints,</a> <a data-t="2062">computational, organizational, logistical,</a> <a data-t="2064">that were real at the time.</a> <a data-t="2067">But what happens when those constraints change?</a></p>

<p><a data-t="2069">Some companies are no longer asking,</a> <a data-t="2071">how do I generate those TLS faster?</a> <a data-t="2073">They're asking, what becomes possible</a> <a data-t="2075">when our teams are entirely freed</a> <a data-t="2078">from writing boilerplate code?</a> <a data-t="2080">And the answer they are arriving at</a> <a data-t="2082">looks something like this,</a> <a data-t="2083">a safety monitoring board</a> <a data-t="2085">that doesn't wait for a quarterly report.</a> <a data-t="2087">Instead, they log into a secure, interactive </a><a href="/software/shiny-r/">Shiny</a> <a data-t="2090">with CVars or Teal application,</a> <a data-t="2092">where clinical data is processed end-to-end automatically,</a> <a data-t="2095">from raw data to a publication-ready Kaplan-Meier plot,</a> <a data-t="2099">allowing them to slice and dice adverse events on the fly</a> <a data-t="2102">with the underlying reproducible R code</a> <a data-t="2104">generated in the background.</a></p>
