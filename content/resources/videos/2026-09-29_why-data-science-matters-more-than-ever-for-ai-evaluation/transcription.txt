<p><a data-t="0">What if the hardest part of artificial intelligence is not building tools, but measuring their</a> <a data-t="12">effectiveness?</a></p>

<p><a data-t="14">We live in a world of incredible artificial intelligence capabilities between generative</a> <a data-t="19">assistants, co-pilots, and AI agents, things that are possible today were not even dreamed</a> <a data-t="24">about six months ago.</a> <a data-t="26">It's faster than ever and easier than ever to build rapidly and arrive at concepts and</a> <a data-t="31">ideas that previously would have taken months of time and now can happen in only an afternoon.</a></p>

<p><a data-t="38">But speed does not necessarily equal confidence.</a> <a data-t="41">It's really easy to build something quickly, but it's much more difficult to understand</a> <a data-t="44">if that thing that we've built, whether it's an agent, a tool, or some other AI native</a> <a data-t="49">application is actually behaving the way that we expect and intend.</a></p>

<p><a data-t="53">My name is </a><a href="/people/james-blair/">James Blair</a><a data-t="53"> and I'm a senior product manager at Posit.</a> <a data-t="57">Today we're going to be talking about artificial intelligence evaluations and how we can measure</a> <a data-t="61">and evaluate the behavior of these AI tools and systems, and particularly why data scientists</a> <a data-t="67">are particularly well positioned to succeed at this evaluation process.</a> <a data-t="71">We'll look at ways to measure the input and output of these AI systems, how to effectively</a> <a data-t="77">understand and evaluate whether they're behaving according to the expectations that we have,</a> <a data-t="82">and how scalable infrastructure and tools can help make sure these evaluations happen</a> <a data-t="86">not only in the initial design and build phase, but also throughout the lifetime of these</a> <a data-t="90">AI tools and applications.</a></p>

<h3>Traditional software vs. AI systems</h3>

<p><a data-t="94">If we look at the difference between traditional software development and the AI systems that</a> <a data-t="98">we see today, it's clear that they don't behave the same.</a> <a data-t="102">Traditional software, the same input would always lead to the same output.</a> <a data-t="105">This made it easy to test.</a> <a data-t="107">We could create tests that verified the output that we expected given some set of input,</a> <a data-t="112">and those tests existed to provide scaffolding around how we expect that software to behave</a> <a data-t="117">and alert us to any sort of unexpected changes.</a></p>

<p><a data-t="120">But AI systems behave differently.</a> <a data-t="121">The same input can lead to various outputs and different paths that the AI tool chooses</a> <a data-t="126">to get to that output.</a> <a data-t="128">This doesn't signal that things are wrong necessarily.</a> <a data-t="131">In fact, it's an inherent behavior of these AI systems that they behave in perhaps unexpected</a> <a data-t="137">yet productive and valuable kind of ways.</a></p>

<p><a data-t="141">This variability means that we need to think more carefully about how we evaluate the output</a> <a data-t="146">that's coming out of these kinds of systems, not only the output, but also what's contributing</a> <a data-t="151">to the final decision or outcome that these systems create.</a> <a data-t="155">The key issue here is not just whether a system can respond to a given set of input, but whether</a> <a data-t="159">we understand how that response is generated and how that matches up against the real world</a> <a data-t="165">expectations that we have for these AI systems.</a></p>

<h3>From prototype to production</h3>

<p><a data-t="168">Many AI projects today start with a compelling prototype.</a> <a data-t="173">As we mentioned in the beginning, it's easier than ever to create very compelling demonstrations</a> <a data-t="176">and proof of concepts that even six or 12 months ago were not possible.</a> <a data-t="182">We connect a model to some sort of a tool, a knowledge base, and suddenly we have a working</a> <a data-t="186">example that illustrates the power of these systems.</a></p>

<p><a data-t="190">But these demos are not the same as production-grade systems.</a> <a data-t="193">We have to face the more difficult questions.</a> <a data-t="196">Are we using the right source?</a> <a data-t="197">Does the model reach for the right tool at the right time?</a> <a data-t="200">Does it confidently approach the answer when it doesn't have the appropriate source?</a> <a data-t="206">All of these are questions that have to be considered, not just the final output, but</a> <a data-t="210">how we arrive there.</a></p>

<p><a data-t="212">Looking at just a few examples of different model behaviors or different agent behaviors</a> <a data-t="216">can be misleading.</a> <a data-t="217">We need a way to rigorously test and verify model and agent behavior across a wide spectrum</a> <a data-t="225">of different inputs and paths that the agent might take to arrive at some sort of output.</a></p>

<p><a data-t="230">This work follows an experimental loop, very naturally kind of aligned with traditional</a> <a data-t="237">scientific experiments.</a> <a data-t="238">We provide input, we evaluate what the model does and what the agent does, and then we</a> <a data-t="243">investigate the output to determine why we arrived at a given conclusion or why a specific</a> <a data-t="248">output was provided.</a></p>

<p><a data-t="250">This final output, while valuable, might hide different problems that exist in the actual</a> <a data-t="257">agent journey.</a> <a data-t="258">We might not see the actual sources that were used or the tool calls that were invoked to</a> <a data-t="263">arrive at a specific output.</a> <a data-t="265">Being able to evaluate not just the final output, but everything that goes into that</a> <a data-t="269">final decision becomes critical in understanding and trusting these agent behaviors.</a></p>

<h3>Why data scientists are the right people for AI evaluation</h3>

<p><a data-t="275">In this kind of world, data science brings that necessary structure to this inherently</a> <a data-t="281">uncertain type of problem.</a> <a data-t="283">Data scientists come with a wealth of knowledge around statistical rigor, experiment management,</a> <a data-t="288">and analysis that allow them to work very, very naturally with these AI systems.</a> <a data-t="294">These data scientists understand how to run these experiments, how to provide targeted</a> <a data-t="299">inputs that allow a proper evaluation of the agent system, not just its final output, but</a> <a data-t="305">every sort of intermediate step that might happen along the way.</a></p>

<p><a data-t="308">These data scientists can define the appropriate success criteria, interpret signal from noise,</a> <a data-t="314">and separate meaningful improvements from random variation.</a> <a data-t="318">These data scientists have the ability to make AI evaluation rigorous so that we move</a> <a data-t="323">from just operating off of vibes into a world where we can operate off of trustworthy evidence</a> <a data-t="329">that our systems are behaving the way that we expect, and over time, improving as models</a> <a data-t="333">and other features of these systems improve as well.</a></p>

<blockquote><a data-t="318">These data scientists have the ability to make AI evaluation rigorous so that we move</a> <a data-t="323">from just operating off of vibes into a world where we can operate off of trustworthy evidence</a> <a data-t="329">that our systems are behaving the way that we expect, and over time, improving as models</a> <a data-t="333">and other features of these systems improve as well.</a></blockquote>

<p><a data-t="338">There's no sort of universal metric that proves that AI is working.</a> <a data-t="342">We've seen many different examples in pop culture and other places of AI systems that</a> <a data-t="345">break down in unexpected ways once they hit the real world.</a> <a data-t="349">Use cases from users interacting with chat agents and asking for things that go well</a> <a data-t="354">outside the scope of what that agent was designed to answer to other sort of more nuanced examples</a> <a data-t="359">where AI systems behave confidently or return confident results that are, in fact, factually</a> <a data-t="364">inaccurate.</a></p>

<p><a data-t="365">We have to be able to move from generic scores and evaluations to very specific, detailed</a> <a data-t="370">investigation around how these AI systems behave, and that varies across industries</a> <a data-t="375">and across use cases.</a> <a data-t="377">One metric does not satisfy every sort of AI opportunity.</a> <a data-t="381">Instead, we need to consider what the expectations are for a given agent in its specific domain.</a> <a data-t="387">Data scientists are particularly equipped to deal with this as they bring domain-specific</a> <a data-t="392">knowledge to play along with their understanding of statistical analyses and general data acumen.</a></p>

<p><a data-t="399">If you consider a customer support agent or a policy assistant or a code assistant, all</a> <a data-t="403">these things have similar ingredients, some sort of foundational model, tool calling,</a> <a data-t="408">context, prompts, yet they're expected to behave differently, and the way that users</a> <a data-t="412">interact with these systems are often unique.</a> <a data-t="415">Being able to evaluate each of these systems in its own unique way becomes critical in</a> <a data-t="420">understanding both the behavior of these systems as well as the output that they produce.</a></p>

<p><a data-t="426">We want to make sure that every step along the way, we're evaluating and capturing the</a> <a data-t="431">necessary information to understand that these systems are behaving in expected ways,</a> <a data-t="436">both in initial development as well as in final production.</a></p>

<h3>Evaluation never stops</h3>

<p><a data-t="442">That leads us to this idea that this evaluation never stops.</a> <a data-t="445">It's important to start with this goal in mind.</a> <a data-t="448">When we start building these AI systems, it can be very easy to get caught up in the excitement</a> <a data-t="452">of building something new and exciting, something that feels revolutionary.</a> <a data-t="456">It's exciting, even still today, to build a system that responds to natural language</a> <a data-t="460">requests and does things that even three months ago maybe seemed far-fetched, but we also</a> <a data-t="466">have to consider the fact that we need to think about evaluating these systems from</a> <a data-t="470">the very beginning.</a></p>

<p><a data-t="471">Capturing traces and logs along the way enable us to make sure that these agents are choosing</a> <a data-t="476">the right path, not just today, but also tomorrow.</a> <a data-t="480">These systems evolve as things like models change, the way the toolkits and frameworks</a> <a data-t="485">that these models use evolve and grow over time.</a> <a data-t="488">Our system prompts may be updated regularly based on new domain knowledge.</a> <a data-t="492">As each of these changes are made to this system, we have to make sure that evaluations</a> <a data-t="497">are in place that allow us to understand how these changes impact these AI systems.</a></p>

<p><a data-t="503">Are we seeing improvement where we expect improvement?</a> <a data-t="505">Is the agent continuing to rely on the appropriate sources for its responses?</a> <a data-t="510">This becomes particularly critical as foundational labs introduce newer and newer models with</a> <a data-t="515">more and more capabilities.</a> <a data-t="517">We need to make sure that introducing a new model to our system doesn't cause the behavior</a> <a data-t="521">of that system to dramatically drift from our expectation.</a></p>

<p><a data-t="526">In addition to capturing these logs in our training and in our evaluation, we also need</a> <a data-t="530">to make sure that we're capturing this information as real-world use cases build up with our</a> <a data-t="535">systems and tools.</a> <a data-t="537">Understanding how users are truly interacting with these systems in production enables us</a> <a data-t="541">to understand and continue to verify that our system meets the needs of real use cases</a> <a data-t="547">from real users, not just the test cases that we define in our initial evaluations.</a></p>

<p><a data-t="552">Data scientists are particularly equipped to set this up for success by building any</a> <a data-t="556">evaluations from the beginning and making sure that those evaluations continue to apply</a> <a data-t="561">even after a model or tool or system reaches production.</a> <a data-t="565">These data scientists can work through this data and make sure that they're evaluating</a> <a data-t="570">model performance on a continual basis to understand and make sure that these agent</a> <a data-t="574">systems continue to meet business expectations long after the development is initially complete.</a></p>
