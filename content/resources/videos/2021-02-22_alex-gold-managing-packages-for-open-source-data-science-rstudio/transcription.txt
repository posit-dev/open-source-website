<h3>Repositories and libraries</h3>

<p><a data-t="258">We're going to stick with this metaphor.</a> <a data-t="258">So, your food starts at the grocery store, right?</a> <a data-t="263">It's, like, packaged up. It's on the shelf. <p><a data-t="287">And it's really the same for packages.</a> <a data-t="287">For packages, you know, your grocery store is your repository.</a> <a data-t="291">So, this is sort of an external place where you have all of your packages, and they're stored, sort of ready for you to go in an inert way.</a> <a data-t="297">And then there's your library, and that is sort of your pantry where you keep your packages that are just for you and the things you're going to make.</a> <a data-t="307">And that's sort of how that works.</a></p>

<p><a data-t="307">And so, for many teams, the repository that they use is public, right?</a> <a data-t="315">It might be public CRAN, public bioconductor, public package manager.</a> <a data-t="321">Other teams choose to maintain private repositories.</a> <a data-t="321">Ours could be a package manager, something else.</a> <a data-t="326">That's really fine.</a> <a data-t="326">But the libraries are always private.</a> <a data-t="326">And the libraries are, you know, anywhere there's a kitchen, anywhere there's actual R or Python processes running in the IDE, in a notebook, on RStudio Connect, in a Docker container, right, there's a library attached to that.</a> <a data-t="343">And the shopping process is the install, right?</a> <a data-t="343">So, the sort of packages get from the grocery store repository into your private pantry library via the install.</a></p>

<p><a data-t="348">And so, just to be a little more, like, precise about this, you know, I have these two sort of side by side, but really the way this works is that, like the grocery store and pantries, many libraries are served by one repository, right?</a> <a data-t="366">One repository provides packages for many libraries.</a> <a data-t="366">And so, let's dive in a little bit on, like, how that works.</a></p>

<p><a data-t="373">So, a repository is just a file server.</a> <a data-t="379">It has a bunch of directories indexed in a particular way.</a> <a data-t="379">And so, just to be precise, this is the link.</a> <a data-t="383">You'll note it's a URL, right?</a> <a data-t="383">It's a real, like, link to an internet site for a particular package on CRAN, right?</a> <a data-t="388">Now, CRAN is the main R package repository, public one.</a> <a data-t="388">And so, what you'll see here, right, is, like, this is for Windows.</a> <a data-t="395">It is using the development version of R, R version 4.1.</a> <a data-t="400">It is for the A3 package, which I chose because it is the alphabetically first package on CRAN.</a> <a data-t="405">And it's version 1.0.0.</a> <a data-t="405">And so, this is, like, literally this is the directory structure inside the CRAN repository.</a> <a data-t="411">And so, this is just a directory that sort of organizes in this particular way that R, when you go to install a package, it knows how to sort of walk this tree and get the package and the package versions that you need.</a></p>

<p><a data-t="429">One of the other important aspects of the repository is that the repository is not local.</a> <a data-t="433">It is almost never the case that your repository is on the same machine as where you're actually doing your work.</a> <a data-t="438">Very often, the repository is going to be, like, actually in the cloud.</a> <a data-t="442">It's actually going to be a website, like that URL I just showed you.</a> <a data-t="442">Or sometimes it's going to be an internal networked server.</a> <a data-t="447">But usually, even if you're doing work on, like, RStudio server, it's almost never going to be on the same server.</a> <a data-t="453">It's going to be a different server.</a></p>
