<h3>Background: existing Tableau–R/Python integrations</h3>

<p><a data-t="292">So, before we go there, let's step back to the beginning a</a> <a data-t="299">little bit and kind of look at what has led us to the point where we are today and the work that</a> <a data-t="303">we've done to make these types of extensions possible.</a> <a data-t="303">And so, to really kind of start at</a> <a data-t="309">the beginning, there are two existing mechanisms for integrating Python and R code into a Tableau</a> <a data-t="316">workbook.</a> <a data-t="316">Tabpy is an open source Tableau package, or excuse me, open source Python package that is</a> <a data-t="323">built and maintained and developed by Tableau themselves.</a> <a data-t="323">And this basically exists to allow</a> <a data-t="328">you to execute arbitrary Python code from a Tableau workbook, view the results response back</a> <a data-t="335">into your Tableau environment.</a> <a data-t="335">RServe is a very similar type of functionality where you open up</a> <a data-t="342">an RServe server in some environment, and then you submit arbitrary code for execution into that</a> <a data-t="349">environment.</a></p>

<p><a data-t="349">And here's an example pull from Tableau's documentation on how these types of</a> <a data-t="354">extensions might be invoked.</a> <a data-t="354">So, we have this script function here, and then we, in this case,</a> <a data-t="360">this is an extension using Tabpy.</a> <a data-t="360">So, we define our entire Python process or entire Python script</a> <a data-t="367">here in this string.</a> <a data-t="367">We submit that to our interpreter that ingests the string, interprets</a> <a data-t="374">and executes the code, returns the result, and then we pass in individual values or arrays of</a> <a data-t="379">values from our Tableau workbook.</a></p>

<h3>The Tableau Analytics Extensions API</h3>

<p><a data-t="463">Now, moving forward, right?</a> <a data-t="463">Again, we've started back at the beginning.</a> <a data-t="463">Tableau released this</a> <a data-t="470">Tableau Analytics Extensions API, I think it's now been a couple of years ago.</a> <a data-t="470">And this is really</a> <a data-t="476">kind of the building block for all the work that we're going to highlight today.</a> <a data-t="476">This Analytics</a> <a data-t="480">Extensions API is actually the kind of the foundational piece of the TabPy integration</a> <a data-t="487">that they've done.</a> <a data-t="487">And so, this same framework is what we've used to provide access to the</a> <a data-t="497">extensions that we're going to highlight today.</a></p>

<p><a data-t="497">I'm not going to go into too much detail here.</a> <a data-t="497">The</a> <a data-t="502">goal here today is not to be a comprehensive deep dive into all the nitty gritty components</a> <a data-t="508">of the Tableau Analytics Extensions API, but rather to give enough information to understand</a> <a data-t="513">kind of what's going on and why we've decided to go in the direction that we've gone with the</a> <a data-t="518">extensions that we're providing access to.</a> <a data-t="518">The main thing I think to understand here is that</a> <a data-t="525">this Extensions API is really just a contract that exists between Tableau and some external service,</a> <a data-t="531">right?</a> <a data-t="531">It doesn't matter what that service is.</a> <a data-t="531">It doesn't matter what it's implemented in.</a> <a data-t="531">It</a> <a data-t="535">doesn't matter what language is it.</a> <a data-t="535">It doesn't matter what it's doing, right?</a> <a data-t="535">As long as it</a> <a data-t="539">obeys the contract, it works.</a></p>

<h3>Comparing old and new approaches</h3>

<p><a data-t="2022">So, let's contrast for a moment the two different approaches, right?</a> <a data-t="2029">We talked about how, in the beginning, we have tabpy, we have rserv as existing integration points for executing R and Python code within Tableau.</a> <a data-t="2040">The pattern for those extensions is what we're seeing here, right?</a> <a data-t="2040">I have some script function, and then the first argument to that script function is the full script that I want executed.</a> <a data-t="2052">In this case, it's the entire Python script that allows me to do this clustering of data points.</a></p>

<p><a data-t="2060">Just to reiterate some of the challenges of this particular approach, it requires that, as the Tableau user, I have the ability to, or I have the understanding and the knowledge, to write the script,</a> <a data-t="2069">or I have the ability to rely on somebody else that can write the script, and then I can copy and paste it in.</a> <a data-t="2075">I don't really have a great way of debugging this, right?</a> <a data-t="2079">I can submit the script.</a> <a data-t="2079">If it errors out, Tableau will tell me that an error occurred, but it doesn't give me a lot of additional information about where that error happened or what the cause of the error was,</a> <a data-t="2088">and it becomes a very kind of repetitive trial and error process to get something like this working.</a> <a data-t="2092">I also don't have any sort of syntax highlighting or any other developer help when it comes to writing and creating the script inside of Tableau.</a></p>

<p><a data-t="2100">The last thing, this is just, this is my own kind of, you know, again, personal perspective on this,</a> <a data-t="2105">is it's also a little bit nerve-wracking to me that this is just arbitrary code execution in some sort of remote environment.</a> <a data-t="2111">I don't know what I'm, I could put anything in this string, and my remote server is going to try to execute that.</a> <a data-t="2116">Hopefully, I'm not putting anything malicious here, but if I am, it's still going to try to execute it on the back end.</a></p>

<h3>Advantages of the RStudio Connect approach</h3>

<p><a data-t="2202">So, what are some of the advantages of this particular approach?</a> <a data-t="2202">Well, we've talked about some of them, but just to kind of revisit a few.</a> <a data-t="2210">One is, this is the only solution that exists today where you could use both R and Python extensions from the same exact Tableau workbook.</a> <a data-t="2222">Right?</a> <a data-t="2222">The other solutions, the existing solutions today, like RServe and TabPy work.</a> <a data-t="2229">We've seen customers utilize those, but you have to choose one or the other.</a> <a data-t="2229">You can't support RServe and TabPy execution from the same workbook or from the same Tableau worksheet.</a></p>

<p><a data-t="2242">It has to be one or the other.</a> <a data-t="2242">With the extensions that are hosted on RStudio Connect, because you can host R and Python extensions in the same location, you can use R and Python extensions alongside one another inside the same Tableau workbook.</a> <a data-t="2252">You also have the advantage of the enterprise-level security that RStudio Connect provides.</a> <a data-t="2256">Access control, you have a very, all processes on RStudio Connect are sandboxed.</a> <a data-t="2260">You're not allowing arbitrary code execution, but rather you have a predefined functionality within an extension.</a> <a data-t="2265">That extension gets invoked when it's called from Tableau, but Tableau users don't have the ability to pass arbitrary code into RStudio Connect.</a> <a data-t="2277">And then all of these extensions are behind the authentication layer that RStudio Connect implements.</a> <a data-t="2282">So, when we set up RStudio Connect to refer to these extensions, we do so by supplying an API key that is then used whenever these extensions are invoked.</a></p>

<p><a data-t="2294">This third point is one that I think is most significant, and that's the fact that R and Python developers can be separate from your Tableau developers, right?</a> <a data-t="2297">We could have a team of statisticians and data scientists that are building these kinds of extensions and providing them on RStudio Connect,</a> <a data-t="2308">and those developers can be entirely separate from the business analysts that are using Tableau or the Tableau developers that are building the workbooks.</a> <a data-t="2315">I don't have to be an expert in both sides, right?</a> <a data-t="2320">Personally, I find myself doing a lot of R and Python development.</a> <a data-t="2325">I don't spend a lot of time in Tableau, right?</a> <a data-t="2325">I don't consider myself a great Tableau developer, even now after spending a lot of time in the product as we've worked through this process.</a></p>

<p><a data-t="2336">But what that means is I can use what works for me, right?</a> <a data-t="2336">I can use the tool that's right for me, and I can build machine learning models, I can build business logic, I can build whatever I want to using R and Python,</a> <a data-t="2346">and then I can easily make that functionality available to my Tableau developers, who might not spend a lot of time in R and Python, but they're really, really good at Tableau, right?</a> <a data-t="2356">This is the idea that we started with at the beginning.</a> <a data-t="2356">Let's use the right tool for the job, and this is all about enabling that choice even further.</a></p>

<p><a data-t="2365">The last point that I'll mention here is environment management provided by RStudio Connect.</a> <a data-t="2369">So, one of the challenges that exists today with tools like RServe and TabPy is how do we make sure that the right packages, the right modules, the right environments are in place so that when we submit code to be executed, it executes in the manner we expect, right?</a> <a data-t="2380">If I try to load the </a><a href="/software/tidyverse/">tidyverse</a><a data-t="2380">, but my RServe environment doesn't have the tidyverse, then I've got to go through some process to contact the admin of that environment, have them make the tidyverse available, then try publishing or then try executing my code again.</a> <a data-t="2393">RStudio Connect is different in the sense that any time we publish any extension, whether it's built in Python or R, the environment is automatically recreated and managed for us on the RStudio Connect side.</a> <a data-t="2403">All that happens automatically.</a> <a data-t="2406">I can have different versions of different packages used by different extensions, and it's all being managed by RStudio Connect.</a></p>
