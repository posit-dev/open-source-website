<h3>Shiny vs. Streamlit</h3>

<p><a data-t="619">So when we came out with Shiny for Python,</a> <a data-t="624">a lot of people out there are already using Shiny for R.</a> <a data-t="627">So some people had this kind of a reaction.</a> <a data-t="633">And other people said something like this.</a> <a data-t="637">But it's just so easy to throw something up</a> <a data-t="660">with Streamlit.</a> <a data-t="641">How many people here have heard of Streamlit?</a> <a data-t="644">Okay, plenty of you.</a></p>

<p><a data-t="646">And we've gotten this question a lot</a> <a data-t="648">since the introduction of Shiny for Python,</a> <a data-t="650">because Streamlit is,</a> <a data-t="653">as smilodon138 says,</a> <a data-t="656">just so easy, right?</a> <a data-t="658">So I wanted to just take a moment</a> <a data-t="660">to unpack this claim a little bit.</a> <a data-t="662">And the promise of Streamlit</a> <a data-t="665">is that you can start with a normal script.py</a> <a data-t="669">that's just a straight linear set</a> <a data-t="672">of data analysis function calls.</a> <a data-t="696">And with Streamlit, you can take exactly that script,</a> <a data-t="680">sprinkle in a few Streamlit statements,</a> <a data-t="682">and boom, you have an interactive application.</a></p>

<p><a data-t="686">And even if you've never seen Shiny before this talk,</a> <a data-t="688">you already know that Shiny doesn't do that, right?</a> <a data-t="690">That Shiny has this form of a UI and a server</a> <a data-t="695">and these little functions with decorators.</a> <a data-t="697">It is asking you to pour your code into its form.</a></p>

<p><a data-t="722">So the way Streamlit is able to do this,</a> <a data-t="707">because that's super cool, right?</a> <a data-t="708">Very nice to be able to just take your script</a> <a data-t="710">and sprinkle in some Streamlit.</a> <a data-t="711">And the way they're able to do this is this.</a> <a data-t="713">Streamlit's architecture allows you to write apps</a> <a data-t="715">the same way you write plain Python scripts.</a> <a data-t="737">To unlock this, Streamlit apps have a unique data flow.</a> <a data-t="720">Anytime something must be updated on the screen,</a> <a data-t="722">Streamlit reruns your entire Python script</a> <a data-t="724">from top to bottom.</a> <a data-t="725">Nobody else does this.</a> <a data-t="746">This is only Streamlit.</a></p>

<p><a data-t="729">And it really is that easy.</a> <a data-t="732">It is true.</a> <a data-t="733">I'm not here to debunk Streamlit's ease of use.</a> <a data-t="736">It is like you might learn Streamlit by accident.</a> <a data-t="741">You could write a Streamlit app falling out of bed.</a> <a data-t="743">It's that easy.</a></p>

<p><a data-t="746">Now, granted, it's running the entire script</a> <a data-t="749">every time you move a slider,</a> <a data-t="751">every time you click a button.</a> <a data-t="752">So as a result, by default,</a> <a data-t="755">it does have slow performance.</a> <a data-t="756">And there's only so much control you can have</a> <a data-t="759">when it's running the entire script</a> <a data-t="761">every time anything changes.</a> <a data-t="762">You can't opt out of that behavior.</a> <a data-t="764">So that means as your Streamlit apps</a> <a data-t="767">get just a little bit more complicated,</a> <a data-t="769">you are actually left in quite a bad place.</a> <a data-t="772">So they have introduced some features</a> <a data-t="773">like caching callbacks and session state</a> <a data-t="776">that are designed to let you work around</a> <a data-t="779">the top-to-bottom execution model.</a></p>

<p><a data-t="781">So I can very much endorse Streamlit for simple apps.</a> <a data-t="785">And I think they made some really fantastic,</a> <a data-t="787">interesting choices.</a> <a data-t="789">But for the complicated apps,</a> <a data-t="791">you're putting yourself and your users in danger</a> <a data-t="794">because it is very tricky to get</a> <a data-t="795">that kind of application correct.</a></p>

<p><a data-t="798">So in contrast, Shiny is easy,</a> <a data-t="801">though not as easy as Streamlit.</a> <a data-t="803">But it is scalable.</a> <a data-t="805">And the history of Shiny is a history of people</a> <a data-t="809">getting so much value out of this framework</a> <a data-t="812">without being web developers,</a> <a data-t="814">but building sometimes quite complex apps</a> <a data-t="818">and getting huge results from those apps.</a> <a data-t="822">And the kinds of stories I could tell you</a> <a data-t="824">about the kinds of accomplishments</a> <a data-t="826">people have made on their Shiny apps</a> <a data-t="828">would, you know, gives me goosebumps</a> <a data-t="829">just thinking about it.</a></p>

<p><a data-t="830">So I would sum it up by saying</a> <a data-t="834">the meantime from getting started</a> <a data-t="836">to having something of value,</a> <a data-t="838">it's Streamlit, it's incredible.</a> <a data-t="840">Like within 10 seconds, you have an interactive plot.</a> <a data-t="843">And with Shiny, maybe it takes you 60 seconds, okay?</a></p>
