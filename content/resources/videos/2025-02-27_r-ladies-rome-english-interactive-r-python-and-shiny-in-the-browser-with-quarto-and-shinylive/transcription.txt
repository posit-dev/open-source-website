<h3>WebAssembly, WebR, and Pyodide</h3>

<p><a data-t="497">And so that's why we are entering the world</a> <a data-t="499">of interactive R and Python in the browser.</a> <a data-t="503">So running code directly in the browser</a> <a data-t="505">opens the door for many new exciting uses</a> <a data-t="509">of data science on the web.</a></p>

<p><a data-t="512">And the two primary technologies</a> <a data-t="514">that we'll be talking about is,</a> <a data-t="517">or we'll be talking about several technologies,</a> <a data-t="519">but these are brought to you thanks to WebR and Pyodide.</a> <a data-t="524">But before we talk about them,</a> <a data-t="526">let's talk about another tool called WebAssembly.</a></p>

<p><a data-t="531">So WebAssembly, or sometimes called WASM,</a> <a data-t="536">is a low-level, high-performance binary instruction</a> <a data-t="541">and it allows compiled languages like C or C++</a> <a data-t="545">to run in web browsers at near native speeds.</a> <a data-t="550">So C and C++ code is compiled by something called Emscripten.</a> <a data-t="555">Emscripten takes the C or C++ code as input.</a> <a data-t="560">It produces WASM as a result.</a> <a data-t="563">And once it's in WASM,</a> <a data-t="565">you can run it in any browser that supports WASM,</a> <a data-t="569">which in modern browsers is actually most of them.</a></p>

<p><a data-t="574">Python has had a browser solution</a> <a data-t="577">for a while called Pyodide.</a> <a data-t="579">So what Pyodide does is compiles</a> <a data-t="581">the Python interpreter CPython to WebAssembly</a> <a data-t="585">using Emscripten, and then it makes it possible</a> <a data-t="588">to run Python in the browser.</a></p>

<p><a data-t="592">And relatively more recently,</a> <a data-t="594">now R has a similar solution with WebR.</a> <a data-t="598">So WebR is the WebAssembly version of R</a> <a data-t="601">that has been compiled to run in the browser.</a> <a data-t="604">It's an open-source project primarily driven by Posit,</a> <a data-t="607">and thanks to the amazing work of many folks,</a> <a data-t="610">but especially </a><a href="/people/george-stagg/">George Stagg</a><a data-t="610"> and Lionel Henry,</a> <a data-t="613">it's now possible to run R code directly in a web browser</a> <a data-t="617">without the need of traditional servers to execute the code.</a> <a data-t="621">So essentially what that means</a> <a data-t="623">is a user can visit a website and run R code directly,</a> <a data-t="627">so without needing R installed on their device.</a> <a data-t="631">All that is required is a web host server</a> <a data-t="634">like Netlify or GitHub Pages.</a></p>

<h3>Introduction to Quarto</h3>

<p><a data-t="940">Quarto is a next generation open source publishing system.</a> <a data-t="945">So it is often called the next evolution</a> <a data-t="948">or the next generation of our markdown.</a> <a data-t="951">So it's expanded upon our markdown.</a> <a data-t="953">What we have done at Posit is taken everything</a> <a data-t="956">that we learned over the past 10 years</a> <a data-t="959">to develop a system like Quarto.</a></p>

<p><a data-t="962">One of the things about Quarto, it's inherently multilingual.</a> <a data-t="966">So right now it supports R, Python, Julia and Observable,</a> <a data-t="971">but it's been designed so that we can add new languages</a> <a data-t="974">in the future.</a></p>

<p><a data-t="977">Another thing that we've learned is R markdown</a> <a data-t="979">has a lot of packages that does a lot of things.</a> <a data-t="983">If you are an R markdown user,</a> <a data-t="984">you might know like use shringen if you wanna do slides</a> <a data-t="987">and </a><a href="/software/bookdown/">bookdown</a><a data-t="987"> if you wanna do books.</a> <a data-t="990">But Quarto has a shared expression</a> <a data-t="992">for all these core features.</a> <a data-t="994">So what that means is if you do a tab set in a Quarto book,</a> <a data-t="998">it looks the same as a tab set in a Quarto presentation.</a></p>

<p><a data-t="1002">And the idea behind Quarto is to create dynamic content</a> <a data-t="1006">with Python and R and Julia and Observable.</a> <a data-t="1010">And then another thing is it enables</a> <a data-t="1013">single source publishing.</a> <a data-t="1015">So the idea of creating notebooks or dashboards</a> <a data-t="1018">or books, et cetera, from one source.</a></p>

<p><a data-t="1021">And I will say there are many great resources about Quarto.</a> <a data-t="1025">We're not gonna talk about everything about Quarto.</a> <a data-t="1028">At this time, I'm happy to share the resources.</a> <a data-t="1031">I would say that the Quarto documentation site</a> <a data-t="1034">is absolutely incredible.</a> <a data-t="1036">It is very detailed and how to get started,</a> <a data-t="1039">how to use Quarto.</a> <a data-t="1041">I gave a talk a couple of years ago at R Ladies St. Louis</a> <a data-t="1044">that I'm happy to share that went more into detail</a> <a data-t="1047">in terms of like, you know, getting set up in RStudio</a> <a data-t="1050">and rendering documents and things like that.</a> <a data-t="1052">But for today, I'm just going to be talking</a> <a data-t="1055">about the most critical parts of Quarto</a> <a data-t="1057">that you need to know in order to use WebR</a> <a data-t="1061">and PyEdite in Quarto documents.</a></p>

<h3>Anatomy of a Quarto document</h3>

<p><a data-t="1066">So first, the anatomy of a Quarto document.</a> <a data-t="1073">So a Quarto document has an extension QMD.</a> <a data-t="1073">The first part that we're going to talk about</a> <a data-t="1075">is what is called the YAML heading.</a> <a data-t="1078">So it is denoted by these three dashes</a> <a data-t="1081">and then a key value pairs within these dashes.</a> <a data-t="1084">So the key, for example, can be title</a> <a data-t="1087">and the value is ggplot2-demo.</a></p>

<p><a data-t="1090">And the YAML heading contains the metadata</a> <a data-t="1094">for your document.</a> <a data-t="1095">So in this case, it's saying,</a> <a data-t="1097">I want to produce an HTML format.</a> <a data-t="1100">I can provide additional options like code full true</a> <a data-t="1104">means like the code within the document</a> <a data-t="1107">should collapse so that it's not immediately visible</a> <a data-t="1110">unless somebody clicks it to open it up.</a> <a data-t="1114">And so the YAML heading, just to reiterate,</a> <a data-t="1117">is the kind of metadata of your document.</a></p>

<p><a data-t="1122">The next part to talk about is the markdown text.</a> <a data-t="1125">So markdown is a lightweight way of writing formatted text</a> <a data-t="1130">and in a way that it looks very readable.</a> <a data-t="1134">You can do things like, for example, here in line eight,</a> <a data-t="1138">the two pound signs mean this is a heading.</a> <a data-t="1141">So this will be rendered as a heading.</a> <a data-t="1143">You can do things like embed images, links, tables,</a> <a data-t="1148">format your text, all sorts of things.</a> <a data-t="1151">But the really nice thing about markdown</a> <a data-t="1153">is that once you learn it, it's easily readable</a> <a data-t="1158">when you say, put it up on GitHub.</a> <a data-t="1162">It doesn't come out in a very nested,</a> <a data-t="1165">difficult to read format.</a> <a data-t="1166">It looks like text.</a></p>
