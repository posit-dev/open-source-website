<h3>Abstractions</h3>

<p><a data-t="203">So I think, like when I think today, like if I was going to sit down and teach someone data science,</a> <a data-t="211">like what would I teach them?</a> <a data-t="213">I, you know, I still love programming.</a> <a data-t="217">I still love to produce code.</a> <a data-t="219">I pretty strongly believe that reading code is still really important, particularly if you're doing data science.</a> <a data-t="228">But it's clear that like writing, the ability to write code is much less important than it's ever been.</a></p>

<p><a data-t="234">But what is still important?</a> <a data-t="236">I think some of these abstractions are really useful to know.</a> <a data-t="240">So when I kind of look back at my work, you know, I think one of the really important things is like thinking about tidy data.</a> <a data-t="247">Like this idea that it's really useful to get your data into a form where every column is a variable and every row is an observation.</a> <a data-t="255">It's probably like easy now to not have tidy data because a coding agent will just grind away at the problem.</a> <a data-t="263">It will solve it using like whatever horrendous, awful code it has to do to work with whatever structure your data is currently in.</a> <a data-t="273">But I also believe that if you up front say, hey, make sure my data is tidy, you're going to end up with code that is easier to understand.</a> <a data-t="281">It's going to be easier for the agent to write, and it's going to be easier for you to verify that it's correct.</a></p>

<p><a data-t="287">So I think the principles of tidy data is still really, really important, even if a lot of the knowledge of like how do I tidy this specific data set maybe is less important because an agent might be able to figure that out today.</a></p>

<p><a data-t="303">The other thing that I think about is about </a><a href="/software/ggplot2/">ggplot2</a><a data-t="303"> and the grammar of graphics.</a> <a data-t="309">And certainly today like does it matter if you know the theme syntax for ggplot2 so you can control the size of the font or the number of ticks on an axis or the angle at which those ticks are?</a> <a data-t="322">That's probably, that's now I think safely information that you can just allow to fall out of your brain and an agent to take over.</a></p>

<p><a data-t="330">But the fundamental idea of the grammar of graphics, I think that is still so incredibly powerful because it gives you a cognitive framework for understanding visualizations, and it gives you a precise technical vocabulary to talk about them.</a> <a data-t="347">And I think that's going to pay off regardless of whether you're talking to another human, formulating the thoughts in your head, or communicating them to an agent.</a></p>

<blockquote><a data-t="330">But the fundamental idea of the grammar of graphics, I think that is still so incredibly powerful because it gives you a cognitive framework for understanding visualizations, and it gives you a precise technical vocabulary to talk about them.</a></blockquote>

<p><a data-t="357">And so to me like the grammar of graphics, like the core idea is when you produce a visualization, that's fundamentally a mapping from things in your data, variables in your data, to aesthetic properties that you can perceive like color and shape and size.</a> <a data-t="372">That's mediated by a scale, that's what controls the details of going from a number to a color or an enum to a shape.</a> <a data-t="382">It's rendered by a geometric mark like a point or a line or a rectangle, optionally transformed by some statistics, maybe you're doing a histogram, maybe you're doing a box plot, you're not displaying the raw data anymore, you're displaying some distribution or summary.</a> <a data-t="398">And finally, all of that's going to be laid out on a coordinate system, typically Cartesian, but also very commonly if you're working with a map, you don't want to use a Cartesian coordinate system, or if you are working in polar coordinates, which is often also very useful.</a></p>

<p><a data-t="415">So I believe those like, those abstractions are still powerful and important, because they give you a way to break up these like big thorny problems into smaller self-contained pieces.</a> <a data-t="430">When you have those abstractions, you have a better ability to think about a problem, and you have a better ability to communicate that to an agent.</a></p>

<p><a data-t="440">So abstractions are important, and I think one of the things that's exciting to me is that AI gives us the opportunity to bring those abstractions to new audiences.</a> <a data-t="453">So one thing that my team has been working on recently, Thomas Peterson, Tian Vandenbrand, and George Stack have been working on is </a><a href="/software/ggsql/">GGSQL</a><a data-t="453">.</a> <a data-t="464">And if you know what ggplot2 is, and you know what SQL is, you can basically guess what ggsql is.</a> <a data-t="470">It's a SQL-inspired syntax for the grammar of graphics.</a></p>

<p><a data-t="474">So this is what ggsql looks like.</a> <a data-t="476">It starts out with some, you know, regular SQL code.</a> <a data-t="481">You're going to generate a data set, and then you're going to visualize it.</a> <a data-t="485">Here we're mapping the build length to the x position, the build depth to the y position, the body map to the fill color.</a> <a data-t="492">We're going to visualize that using a point.</a> <a data-t="496">We're also going to add on top of that an annotation, a line that shows us a slope of 0.4 with a y-intercept of negative 1.</a> <a data-t="505">We're going to map the fill body mass to the fill color using a bin scale, and then we're going to add some labels.</a> <a data-t="514">And then we run that with ggsql, we get something that looks like a very classical ggplot2 graphic,</a> <a data-t="520">but now we have something that's 100% accessible to someone that only works in SQL.</a></p>

<p><a data-t="526">And I'm pretty excited about this, because I think the grammar of graphics is an incredibly powerful framework for thinking about visualization,</a> <a data-t="535">and this is not something that SQL users have had access to in the past.</a> <a data-t="540">The other reason we've been working on ggsql is it's also sometimes nice to generate a visualization in a language that's kind of guaranteed to be safe.</a> <a data-t="549">If you're generating R code to create ggplot2 or Python code to create matplotlib, that code can do anything.</a> <a data-t="557">Hopefully it's only going to create the plot, but it could be doing whatever to your computer.</a> <a data-t="562">Nice thing about SQL, you can run this and you can know this isn't going to go and delete files,</a> <a data-t="568">it's not going to read your passwords and email them to maybe Grok.</a></p>
