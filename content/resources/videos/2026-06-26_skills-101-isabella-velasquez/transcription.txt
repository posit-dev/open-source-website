<h3>What skills are</h3>

<p><a data-t="186">In terms of what skills are,</a> <a data-t="188">at their core skills are Markdown files,</a> <a data-t="191">and Markdown is a lightweight markup language</a> <a data-t="195">with plain text formatting.</a> <a data-t="197">If you've ever used R Markdown or </a><a href="/software/quarto/">Quarto</a><a data-t="197">,</a> <a data-t="200">you have used Markdown.</a> <a data-t="202">And these files live in a folder</a> <a data-t="204">that your coding assistant can find.</a> <a data-t="207">And many, many coding assistants</a> <a data-t="210">follow the specifications for skills.</a> <a data-t="214">And so they know where to look</a> <a data-t="215">and what to do when they find these files.</a></p>

<p><a data-t="218">And even though I mentioned coding assistants specifically,</a> <a data-t="223">skills are actually supported in other sorts of programs.</a> <a data-t="226">If you use Cloud Cowork, which is a desktop app,</a> <a data-t="230">those actually support skills as well.</a> <a data-t="232">But just in the context of today</a> <a data-t="234">and this conference and us as you are users,</a> <a data-t="237">I'm going to be focusing specific on coding assistants</a> <a data-t="240">like Posit Assistant and Cloud Code.</a></p>

<p><a data-t="243">And so in terms of these files and folders,</a> <a data-t="246">they can live globally.</a> <a data-t="248">And so this means that every time</a> <a data-t="252">that you go to work with your coding assistant,</a> <a data-t="255">it'll be there installed and ready to go.</a> <a data-t="258">And skills can also be installed at a project level.</a> <a data-t="262">So if you need a specific skill for a specific project,</a> <a data-t="266">you could do that as well.</a> <a data-t="267">And it won't be available to every single project</a> <a data-t="270">that you open up.</a></p>

<h3>Anatomy of a skill</h3>

<p><a data-t="275">And so here's an example of what that looks like.</a> <a data-t="278">So if you imagine the left-hand side is my file explorer,</a> <a data-t="282">I have a project open where I have a .cloud folder,</a> <a data-t="287">within that, a skills folder,</a> <a data-t="289">within that, a shinybslib folder,</a> <a data-t="291">and then within that, a skill.nd,</a> <a data-t="294">that markdown file that defines a skill.</a> <a data-t="297">And because it's a markdown file, like a readme file,</a> <a data-t="300">you can click that and open it up</a> <a data-t="302">and take a look at what is inside.</a></p>

<p><a data-t="306">And in terms of the anatomy of a skill,</a> <a data-t="309">what actually defines a skill in this markdown file?</a> <a data-t="312">So if you have used Quarto or R Markdown before,</a> <a data-t="318">you may be familiar with this YAML header.</a> <a data-t="321">So it's denoted by three dashes.</a> <a data-t="324">And then inside those three dashes,</a> <a data-t="327">there is a key value pair.</a> <a data-t="329">So the key in this case would be name.</a> <a data-t="332">The value is shinybslib.</a></p>

<p><a data-t="336">And so the first required piece of a skill is this name,</a> <a data-t="342">which must also match the folder name</a> <a data-t="345">in which it is contained.</a> <a data-t="347">That's how the assistant knows</a> <a data-t="348">to actually go ahead and find it.</a></p>

<p><a data-t="352">And then second is the description,</a> <a data-t="355">which is probably the most important field.</a> <a data-t="358">I think this can be a little bit misleading</a> <a data-t="360">because it sounds like, oh, a description.</a> <a data-t="363">I just need to write out what exactly this,</a> <a data-t="366">what description of the skill.</a> <a data-t="368">But in fact, this skill is how the model decides</a> <a data-t="373">whether or not to load the full skill.</a> <a data-t="376">It'll read this, it'll search for keywords and context,</a> <a data-t="380">and then decide yes or no in terms of,</a> <a data-t="383">yes, I'm going to use this skill.</a> <a data-t="385">And so even though it sounds like</a> <a data-t="387">it's a description for humans,</a> <a data-t="389">it's in fact a description for the model.</a> <a data-t="392">And so it's very important to know,</a> <a data-t="397">or to write a very good description</a> <a data-t="399">so that your skill is loaded appropriately.</a></p>

<p><a data-t="404">And then below the YAML header is your actual content.</a> <a data-t="408">So these are the instructions and the worked examples,</a> <a data-t="412">the guardrails, whatever you want your model to do</a> <a data-t="416">whenever you give it a command.</a></p>

<h3>How progressive disclosure works</h3>

<p><a data-t="418">And in terms of how it works,</a> <a data-t="421">the coding assistant would load skills</a> <a data-t="423">through something that's called progressive disclosure.</a> <a data-t="427">It doesn't load every single skill up front.</a> <a data-t="430">Instead, it keeps a lightweight index</a> <a data-t="433">of just those names and descriptions.</a> <a data-t="435">And at startup, that's all that it reads.</a></p>

<p><a data-t="440">Then you give the coding agent a command,</a> <a data-t="443">like, hey, build me a </a><a href="/software/bslib/">BSLib</a><a data-t="443"> dash.</a> <a data-t="446">Hey, build me a BSLib dashboard.</a> <a data-t="449">At this point, this is when the agent would,</a> <a data-t="453">or the coding assistant would scan all those descriptions</a> <a data-t="456">and then again, look for those keywords and be like,</a> <a data-t="459">hey, does this match the command</a> <a data-t="461">that I was just given or not?</a> <a data-t="464">And again, this is meant to be just enough</a> <a data-t="466">to know whether or not the skill is relevant.</a> <a data-t="470">And only then, if it assesses, yes,</a> <a data-t="474">this skill is relevant,</a> <a data-t="476">will the coding assistant read in the full skill MD file.</a> <a data-t="480">And then at this point,</a> <a data-t="482">the coding assistant follows the different instructions</a> <a data-t="486">based on whatever is specified</a> <a data-t="489">in the actual body of the skill.</a></p>

<h3>Skills vs. agent.md</h3>

<p><a data-t="493">And you may have heard of something called agent.md</a> <a data-t="498">or claw.md.</a> <a data-t="500">And so agent is more general,</a> <a data-t="503">claw.md is specific for clawed code.</a> <a data-t="508">And there are a lot of similarities.</a> <a data-t="511">Clawed or agent.md are also markdown files</a> <a data-t="514">with instructions for your model</a> <a data-t="517">and your coding assistant in terms of telling it what to do.</a></p>

<p><a data-t="521">However, one issue of putting everything within claw.md</a> <a data-t="526">is this idea of context limits.</a> <a data-t="529">So your model can only hold so much information</a> <a data-t="533">at a particular time.</a> <a data-t="535">And if your agent.md file is really, really big,</a> <a data-t="539">it's going to hit its context limit really fast.</a> <a data-t="543">And the issue with that is as you add on</a> <a data-t="545">more and more instructions,</a> <a data-t="547">your model doesn't actually necessarily get better.</a> <a data-t="550">They can get worse.</a> <a data-t="551">They can start to drift.</a> <a data-t="554">They forget the rules that you gave it.</a> <a data-t="556">It starts to hallucinate and so on.</a> <a data-t="559">And then of course, as a user,</a> <a data-t="562">what this means is every time you are opening up a project,</a> <a data-t="567">your agent.md file is read,</a> <a data-t="569">you're using more tokens than you absolutely need,</a> <a data-t="573">which can incur further costs from you.</a></p>

<p><a data-t="576">Versus a catalog of skills,</a> <a data-t="579">which are again focused and it avoids this issue</a> <a data-t="583">by having sort of a playlist only for the task at hand.</a> <a data-t="588">They're small and composable,</a> <a data-t="590">and you can just pick them out as you need them.</a> <a data-t="594">So you and the model are really only paying</a> <a data-t="596">for what you're actually going to be using.</a></p>

<h3>Invoking skills</h3>

<p><a data-t="601">In terms of say you have your collection of skills,</a> <a data-t="604">how do you actually invoke or use your skills?</a> <a data-t="607">There's two different ways.</a> <a data-t="609">One way is explicitly.</a> <a data-t="611">So you can use what's called a slash command.</a> <a data-t="614">So a forward slash and then the name of the skill</a> <a data-t="618">to call the skill by name.</a> <a data-t="619">And you could do this if you say no,</a> <a data-t="621">that you're going to be creating a BS Lib app,</a> <a data-t="627">but more likely you will be doing it automatically.</a> <a data-t="630">So when you say, hey, build me a dashboard</a> <a data-t="633">for so-and-so thing,</a> <a data-t="635">it's going to read those names and descriptions.</a> <a data-t="638">Again, based on it's like a small index,</a> <a data-t="641">it's going to determine based on the context,</a> <a data-t="644">whether or not the skill is relevant.</a> <a data-t="646">And I'll let you know, hey, the skill is loaded.</a> <a data-t="649">You know, in this case, </a><a href="/software/shiny-r/">Shiny</a><a data-t="649"> BS Lib has been loaded.</a> <a data-t="653">And so again, it only works as well as your description,</a> <a data-t="657">which is another reason to spend a little bit of time</a> <a data-t="660">on that field.</a></p>
