<h3>Posit's approach to responsible AI</h3>

<p><a data-t="77">Before we get into the specifics, let's take a moment and step back</a> <a data-t="81">and talk about why Posit and why we care so much about responsible AI.</a> <a data-t="87">At Posit, we've always cared about something called the Prime Directive.</a> <a data-t="91">The Prime Directive comes from John Chambers, who created the S-language at Bell Labs.</a> <a data-t="95">The S-language eventually became R.</a> <a data-t="95">In 2008, he wrote down a rule called the Prime Directive.</a> <a data-t="101">Software for data analysis must be trustworthy, and it must be shown to be trustworthy.</a></p>

<blockquote><a data-t="101">Software for data analysis must be trustworthy, and it must be shown to be trustworthy.</a></blockquote>

<p><a data-t="107">We believe that code is the only way to satisfy the Prime Directive.</a> <a data-t="111">A person can read code, a person can review it, they can test it, and run it again.</a> <a data-t="115">You can't do that with a point-and-click tool, and you can also not do that with a conversation with a chatbot.</a> <a data-t="121">We hold this Prime Directive lens to everything we're building with AI as well.</a> <a data-t="126">We ask whether it can be trusted, and whether that trust can be shown.</a></p>

<p><a data-t="132">In terms of doing responsible AI, there's four principles that we have developed at Posit.</a> <a data-t="138">Keep in mind, this is our current best thinking.</a> <a data-t="141">The AI environment is changing so quickly, these principles might change as well.</a></p>

<p><a data-t="147">But the first principle is code first.</a> <a data-t="150">We believe this is the only way to satisfy the Prime Directive, and nothing changes with the use of AI here.</a> <a data-t="155">Code is inspectable and reviewable, and is the only way to show the analysis is trustworthy.</a> <a data-t="161">Second, we believe that a human should be in the loop.</a> <a data-t="164">The human is the expert, and ultimately the accountable person.</a> <a data-t="169">The AI is the co-pilot, helping the pilot work more efficiently.</a></p>

<p><a data-t="175">Next, we believe that the AI should be session-aware, yet data-private.</a> <a data-t="180">And these two things are often in tension with one another.</a> <a data-t="183">Session-aware means the AI has access to all the context it needs to do correct analysis.</a> <a data-t="189">However, you don't want to expose sensitive data to an LLM or some model provider where that data is not allowed to go.</a></p>

<p><a data-t="198">And then fourth, governed environments.</a> <a data-t="200">A governed environment means the system enforces compliance, not the individual.</a> <a data-t="204">At Posit, we often talk about the pit of success.</a> <a data-t="207">The pit of success is where someone does the right thing without even trying.</a> <a data-t="211">The system is set up in such a way that they have no choice but to fall into the pit of success.</a> <a data-t="216">Throughout this workflow, we're going to look at how we can use Posit Workbench, Posit Connect, and Posit Package Manager to force users into the pit of success.</a></p>
