<p><a data-t="753">So again we see the LLMs can fail at tasks that are central to data analysis.</a> <a data-t="759">And not only do they fail they can cloak these incorrect answers in confident descriptions and it makes it really hard to tell what's correct and what's not.</a> <a data-t="777">That sounds a bit negative.</a> <a data-t="780">I'm going to say that LLMs are still useful for data analysis and we don't need to throw this whole endeavor away just because of evidence like Bluff Bench and Bluff Bench 2.</a> <a data-t="793">It doesn't mean the LLMs are useless anywhere that you're doing anything that you value correctness.</a> <a data-t="800">Instead the task is really to figure out how they can fit into the work and to design around their limitations.</a></p>

<h3>Making it easy to be right</h3>

<p><a data-t="900">Okay. So I said even though they make all these mistakes and like they seem, you know, these mistakes we see in BluffBench are like kind of bad.</a> <a data-t="909">You know, these are not things that we want a human agent to do.</a> <a data-t="912">They're not things we want an LLM agent to do.</a> <a data-t="912">But LLMs still have a use for data analysis.</a> <a data-t="917">They can actually be very useful.</a> <a data-t="917">But we need to make it as easy as possible for them to be right.</a> <a data-t="925">And what this task looks like is constructing the environment, everything that goes around the model, so that it's as easy as possible for the model to sort of fall into correctness.</a> <a data-t="933">We don't want it to have to work very hard to, you know, be right.</a> <a data-t="938">We want it to just fall into this path of correctness.</a> <a data-t="945">And I'm saying build the environment around the model.</a> <a data-t="949">Because typically you control the harness, all of this stuff around the model, like the prompting and the tools and the skills.</a> <a data-t="954">And you're not actually controlling the model itself.</a></p>

<p><a data-t="967">I'm going to talk about two things to construct this ecosystem around the model that makes it easy to be right.</a> <a data-t="973">The first is that code should really be the foundation of what the agent is doing.</a> <a data-t="978">So, you want to have the model write code.</a> <a data-t="983">And then the second is to design the harness with correctness in mind.</a></p>

<p><a data-t="992">Okay. So, when you're making an agent, I think if you want it to be correct, it is really helpful to lean on code.</a> <a data-t="1000">And there's a couple reasons for this.</a> <a data-t="1000">The first is that I think by now many people are familiar with this.</a> <a data-t="1005">But LLMs are actually great at writing code.</a> <a data-t="1009">This is really one of their strengths.</a> <a data-t="1009">And then the second is that, you know, from years of everyone doing data analysis as humans, we've learned that code is great for data analysis.</a> <a data-t="1019">It's reproducible, it's transparent, and it's auditable.</a> <a data-t="1025">And the same things that are true for humans doing data analysis is true for LLMs doing analysis.</a> <a data-t="1029">We shouldn't, you know, abandon these learnings of code just because there's a new tool.</a> <a data-t="1037">So, we want the agent to write code.</a></p>

<p><a data-t="1041">And then we also want to design the harness with correctness in mind.</a> <a data-t="1048">So, for Posit Assistant, we have a lot of prompting that encourages it to prioritize correctness over progress.</a> <a data-t="1052">If you let models sort of go on their own, they often will just kind of advance the analysis forward instead of thinking about correctness, subtlety, statistical rigor.</a> <a data-t="1062">So, we have a lot of prompting encouraging it to follow this path.</a> <a data-t="1069">The second is having tools that serve the same purposes of correctness.</a> <a data-t="1073">So, these are things, again, having code is the foundation of what your agent does.</a> <a data-t="1077">Have the agent run code.</a> <a data-t="1083">You could imagine an agent that, you know, does not run code.</a> <a data-t="1083">You just hand it a CSV, and it computes, you know, in its head the median of columns or the number of rows.</a> <a data-t="1091">Generally, it's going to be a lot less successful than having it run a bit of code, see that result, and then give you the answer.</a></p>

<p><a data-t="1098">And then you also want the agent to have enough access to files and environment and data so that it has a, you know, good chance of building enough context to actually get the answer right.</a> <a data-t="1112">There's often so much nuance in data analysis, and a lot of that comes from, you know, not just the data, but all of the context around that data.</a> <a data-t="1126">And you want the agent to have access to that.</a></p>

<p><a data-t="1138">And it turns out that performance improves when the environment makes it easy to be right.</a> <a data-t="1138">So, we ran an evaluation on Posit Assistant on the Bluff Bench tasks and compared it to the result from the Bluff Bench package that just has a minimal harness in place.</a> <a data-t="1148">All the model can really do there is make a plot.</a> <a data-t="1148">And it turns out that when you have all this stuff wrapped around the model, pushing it towards this path of correctness, performance improves.</a> <a data-t="1157">So, generally, Posit Assistant has done better on this evaluation than just the minimal harness present in Bluff Bench.</a></p>
