<h3>The agentic loop</h3>

<p><a data-t="410">When you're using an AI agent, it has a way to interact with the world.</a> <a data-t="415">We call them tools.</a> <a data-t="416">A tool description looks like this.</a> <a data-t="418">You have a name, you've got some text that describes it to the model, and then a way to tell the LLM how to invoke this tool.</a> <a data-t="426">And what I want you to just get an idea for is what we call the agentic loop.</a> <a data-t="430">This is the lifeblood of an AI agent.</a> <a data-t="432">You have some kind of setup.</a> <a data-t="433">You have a user turn.</a> <a data-t="435">And then each user turn is prompted by someone has sat, typed a question in a box and pressed enter.</a></p>

<p><a data-t="443">Now, because inside a single turn, an assistant might use some tools, every time the assistant uses a tool, barring things like parallel tool calls and various subtleties, but generally every time a tool is used, that's a single back and forth because a request has come back to say, please use this tool.</a> <a data-t="475">And the value of the response has gone back to the model.</a> <a data-t="478">So back and forth and back and forth.</a> <a data-t="479">And that's the loop.</a> <a data-t="480">Read the assistant message.</a> <a data-t="481">We check for tool calls.</a> <a data-t="481">We run the tool calls.</a> <a data-t="483">We send them back.</a> <a data-t="483">We check the assistant message.</a> <a data-t="484">We check if there's tool calls.</a> <a data-t="485">We run the tool calls.</a> <a data-t="486">We send it back.</a> <a data-t="487">And we do it over and over again.</a> <a data-t="489">That's the agentic loop.</a> <a data-t="493">And then eventually the assistant will stop and it'll say, okay, I understand.</a> <a data-t="496">Here's your answer.</a> <a data-t="497">And then we wait for the next turn.</a> <a data-t="498">And that's how things like Posit Assistant work, that's how Claude Code works and Copilot Chat.</a></p>

<h3>Token caching</h3>

<p><a data-t="731">Many of the frontier providers, not everyone, but most, you know, Anthropic and OpenAI certainly, will provide deep discounts if you have cached LLM tokens.</a> <a data-t="740">What I mean by that is that if you send the same thing twice within some predetermined time period, you'll pay a lot less for those tokens the second time.</a> <a data-t="751">OpenAI have a way to do this automatically.</a> <a data-t="754">Anthropic have a manual cache control markers.</a> <a data-t="766">But yeah, these discounts can be very, very deep, like 90% cheaper by using caching.</a></p>

<p><a data-t="772">The way this works is that when you send a user request, like here, you can attach headers.</a> <a data-t="776">This is a cache control header attached to that user message.</a> <a data-t="784">But next time the user sends a message following up from that, everything in blue, the model has seen before.</a> <a data-t="793">And you only pay full price kind of for the latest, which if you imagine a very long conversation with lots and lots of tool calls and lots and lots of turns, the ratio of the new stuff is very small as compared to everything that the model has seen before.</a> <a data-t="825">So you can save a lot of money for you or your company by taking advantage of these caching discounts.</a></p>

<p><a data-t="831">With Posit Assistant, we try and achieve, you know, greater than 80% cache rate hits.</a> <a data-t="837">We can make it up to 90%, but there are some gotchas.</a> <a data-t="844">So if you are thinking of using caching, some top tips.</a> <a data-t="847">Try not to change the system prompt.</a> <a data-t="851">We used to do a thing where the system prompt sent to the model would change depending on what you're doing.</a> <a data-t="857">It was a sort of template system.</a> <a data-t="858">You know, so if you're using R and then you flip to a Python console, the prompt would change to indicate that.</a> <a data-t="862">Unfortunately, you'll find that changing the system prompt completely invalidates the caching.</a> <a data-t="866">It's changing the very start of the message sent to the LLM.</a> <a data-t="869">So you have to pay full price for everything again.</a> <a data-t="870">So as much as possible, try not to change the history if you can.</a></p>

<p><a data-t="874">Also, if you are doing that and you're not trying to change the history, sometimes you can use these XML style tags in your user message that's kind of injected to change the behavior of the model.</a> <a data-t="904">You can change the behavior of the model by putting instructions inside XML tags that look kind of like this.</a> <a data-t="911">And the LLM will listen to those.</a> <a data-t="914">It's not as strong as true system prompting, but it is enough to change the behavior of the system without changing your entire history by changing the system prompt.</a></p>

<p><a data-t="927">That's true of tools too, by the way.</a> <a data-t="928">We used to make various tools available or not available depending on the context in Positron.</a> <a data-t="932">But again, if you change which tools are available, that completely invalidates the cache and you're paying 100% for, you know, 200,000 tokens, 250,000 tokens on the next turn.</a> <a data-t="961">So you gotta be careful.</a></p>

<h3>Managing tool outputs and context</h3>

<p><a data-t="979">So tools are the main way for LLMs to interact with the outside world.</a> <a data-t="982">They're kind of what makes the AI agent able to do some work on your behalf.</a> <a data-t="984">Another top tip for you, manage your tool outputs.</a> <a data-t="998">If you have things like a bash tool or a tool to run R code, don't just naively put the results of that tool into your conversation history.</a> <a data-t="1009">Here's an example where this is sort of, it's not really data related, but some kind of like sysadmin related thing.</a> <a data-t="1015">Someone might print some log files and if they're not careful, you might accidentally get gigabytes of log files in your conversation history.</a> <a data-t="1024">And that's gonna break things.</a></p>

<p><a data-t="1038">Here's a good trick.</a> <a data-t="1039">If the output from a tool happens to do something like that, don't give it straight to the model, write it to disk in some temporary location and give the path to the model instead.</a> <a data-t="1057">Because these models, they're trained to use tools like search tools, read tools, you know, grepping.</a> <a data-t="1064">They're trained to use these tools where they can take very long files.</a> <a data-t="1069">Now this could be millions of lines of code of log files and they're trained to be able to extract, search for and extract partial parts of that without putting the whole thing in your conversation history.</a> <a data-t="1078">Let the model know that it's a truncated output, you know, some end lines, write to disk somewhere and let it know what it should expect.</a> <a data-t="1085">That's really useful.</a></p>

<p><a data-t="1090">If you find that you're using a context a lot with your AI agentic workflows, what you can do is use sub-agents.</a> <a data-t="1096">Sub-agents are useful if you're doing some kind of work and you don't want to use all of that context history.</a> <a data-t="1105">You want to kind of just send off a sub-agent to do that work for you.</a> <a data-t="1109">This is useful because what you can do is as a tool call, you can create a sub-agent.</a> <a data-t="1114">You can set up a tool that can create a sub-agent and what that will do is your sub-agent will have some kind of system prompt that might be different from the main agentic loop and the user message, rather than written by the user, will be written by the model in this tool call.</a> <a data-t="1148">And then this can rip, right?</a> <a data-t="1150">This could be, you know, 200,000, 300,000 tokens, tool calls over and over again, 40 tool calls, 50 tool calls, some kind of long running agentic workflow could happen all inside this sub-agent.</a> <a data-t="1162">But that final message from the assistant when the work has been done can then be taken and then injected back into the original tool loop as a result from this tool.</a> <a data-t="1179">So what you've done is you've compressed all of this work that happened down into a single message of just a few tokens and you've put it inside your main agentic loop and then the assistant can continue.</a></p>

<h3>Guardrails and probabilistic debugging</h3>

<p><a data-t="1305">Okay, I will really quickly say that it's tempting with these tools when you're building your own AI agents to sort of add in as much customization as possible.</a> <a data-t="1314">Oh, maybe the user could add this or that.</a> <a data-t="1316">Maybe we should have some kind of graph-based agentic workflow.</a> <a data-t="1320">Maybe we should have very complex sub-agent definitions, things like that, custom instructions that the user can supply.</a> <a data-t="1325">What I will say is that that stuff's really nice, but do, if you can, instead stick with known protocols and standards that already exist.</a> <a data-t="1333">We learned that these things are much easier for the models to parse, largely because they're trained to do these things.</a> <a data-t="1341">Things like agents.md or copilot.md or whatever, things like skills that just mark down text.</a> <a data-t="1348">Models are good at reading text.</a> <a data-t="1349">Model context protocol, the kind of thing Neil talked about.</a> <a data-t="1352">Models are trained to be able to use the tools from here.</a> <a data-t="1356">Users know how to use those things.</a></p>

<h3>Key takeaways</h3>

<p><a data-t="1537">Try to avoid adding complexity to your agents.</a> <a data-t="1540">Try and keep things as simple as possible because you can do things like prompt your agent to a mile away and back.</a> <a data-t="1550">You can do things like set up very complicated workflows.</a> <a data-t="1553">But what you will find is this time next year, the models are five times as big.</a> <a data-t="1557">They're five times as clever.</a> <a data-t="1558">And all of that work that you spent building those very long prompts, building those workflows are no longer needed.</a> <a data-t="1566">This is called the bitter lesson and it's been around a long time before LLMs.</a> <a data-t="1568">It's a very old AI idea that don't work too hard because the models are going to get better anyway.</a> <a data-t="1577">So yeah, keep it simple.</a> <a data-t="1579">Thanks very much.</a></p>
