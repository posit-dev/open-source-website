<p><a data-t="788">Okay, many of the frontier providers,</a> <a data-t="792">not everyone, but most, you know,</a> <a data-t="794">Anthropic and OpenAI certainly,</a> <a data-t="795">will provide deep discounts if you have cached LLM tokens.</a> <a data-t="800">What I mean by that is that</a> <a data-t="801">if you send the same thing twice</a> <a data-t="803">within some predetermined time period,</a> <a data-t="805">you'll pay a lot less for those tokens the second time.</a> <a data-t="809">OpenAI have a way to do this automatically.</a> <a data-t="811">Anthropic have a manual cache control markers.</a> <a data-t="814">You can do it automatically with Anthropic these days,</a> <a data-t="817">but with PositiveSystem,</a> <a data-t="819">we like the manual cache control markers</a> <a data-t="820">because it lets us do clever things</a> <a data-t="822">with the MFR context and things like that.</a> <a data-t="824">But yeah, these discounts can be very, very deep,</a> <a data-t="826">like 90% cheaper by using caching.</a></p>

<h3>Managing tool outputs</h3>

<p><a data-t="984">Okay, so yeah, so tools are the main way</a> <a data-t="987">for LLMs to interact with the outside world.</a> <a data-t="990">They're kind of what makes the AI agent</a> <a data-t="992">able to do some work on your behalf.</a> <a data-t="994">Another top tip for you, manage your tool outputs.</a></p>

<p><a data-t="998">If you have things like a bash tool</a> <a data-t="1000">or a tool to run R code,</a> <a data-t="1002">don't just naively put the results of that tool</a> <a data-t="1006">into your conversation history.</a> <a data-t="1007">Here's an example where this is sort of,</a> <a data-t="1010">it's not really data related,</a> <a data-t="1011">but some kind of like sysadmin related thing.</a> <a data-t="1013">Someone might print some log files</a> <a data-t="1015">and if they're not careful,</a> <a data-t="1016">you might accidentally get gigabytes of log files</a> <a data-t="1018">in your conversation history.</a> <a data-t="1019">And that's gonna break things.</a></p>

<p><a data-t="1021">The model's not gonna be able to use</a> <a data-t="1024">over a million characters of code.</a> <a data-t="1027">They're not very good at that.</a> <a data-t="1028">They'd be able to pick out individual things,</a> <a data-t="1030">but they wouldn't be able to aggregate, for example.</a> <a data-t="1032">They're not good at that.</a> <a data-t="1033">But not only that,</a> <a data-t="1034">but the next time the user says something,</a> <a data-t="1036">the whole conversation history is gonna break</a> <a data-t="1038">because you've blown up,</a> <a data-t="1039">you filled the context with this log file</a> <a data-t="1041">and there's only a finite amount of space</a> <a data-t="1043">that you can use.</a></p>

<p><a data-t="1044">So here's a good trick.</a> <a data-t="1046">If the output from a tool</a> <a data-t="1048">happens to do something like that,</a> <a data-t="1050">don't give it straight to the model,</a> <a data-t="1052">write it to disk in some temporary location</a> <a data-t="1054">and give the path to the model instead.</a> <a data-t="1057">Because these models,</a> <a data-t="1058">they're trained to use tools like search tools,</a> <a data-t="1060">read tools, you know, grepping.</a> <a data-t="1063">They're trained to use these tools</a> <a data-t="1064">where they can take very long files.</a> <a data-t="1066">Now this could be millions of lines of code of log files</a> <a data-t="1069">and they're trained to be able to extract,</a> <a data-t="1072">search for and extract partial parts of that</a> <a data-t="1075">without putting the whole thing</a> <a data-t="1076">in your conversation history.</a> <a data-t="1077">So there's something like this.</a> <a data-t="1078">Let the model know that it's a truncated output,</a> <a data-t="1080">you know, some end lines,</a> <a data-t="1082">write to disk somewhere</a> <a data-t="1083">and let it know what it should expect.</a> <a data-t="1085">That's really useful.</a></p>

<h3>Using sub-agents to preserve context</h3>

<p><a data-t="1086">If you find that you're using a context a lot</a> <a data-t="1090">with your AI agentic workflows,</a> <a data-t="1093">what you can do is use sub-agents.</a> <a data-t="1096">Sub-agents are useful</a> <a data-t="1097">if you're doing some kind of work</a> <a data-t="1099">and you don't want to use all of that context history.</a> <a data-t="1103">You want to use that all up with your agent.</a> <a data-t="1105">You want to kind of just send off a sub-agent</a> <a data-t="1107">to do that work for you.</a></p>

<p><a data-t="1109">This is useful because what you can do is</a> <a data-t="1111">as a tool call, you can create a sub-agent.</a> <a data-t="1114">You can set up a tool that can create a sub-agent</a> <a data-t="1116">and what that will do is your sub-agent</a> <a data-t="1118">will have some kind of system prompt</a> <a data-t="1119">that might be different from the main agentic loop</a> <a data-t="1123">and the user message, rather than written by the user,</a> <a data-t="1126">will be written by the model in this tool call.</a> <a data-t="1128">And then this can rip, right?</a> <a data-t="1130">This could be, you know, 200,000, 300,000 tokens,</a> <a data-t="1133">pool calls over and over again,</a> <a data-t="1134">40 tool calls, 50 tool calls,</a> <a data-t="1136">some kind of long running agentic workflow</a> <a data-t="1138">could happen all inside this sub-agent.</a></p>

<p><a data-t="1140">But that final message from the assistant</a> <a data-t="1143">when the work has been done</a> <a data-t="1145">can then be taken and then injected back</a> <a data-t="1147">into the original tool loop as a result from this tool.</a> <a data-t="1151">So what you've done is you've compressed</a> <a data-t="1153">all of this work that happened down</a> <a data-t="1155">into a single message of just a few tokens</a> <a data-t="1158">and you've put it inside your main agentic loop</a> <a data-t="1160">and then the assistant can continue</a> <a data-t="1162">and it means that you've used up,</a> <a data-t="1164">you've done a lot of work agentically</a> <a data-t="1167">without using up your context history</a> <a data-t="1169">and it means that the user can continue their conversation,</a> <a data-t="1172">you know, go in a different direction</a> <a data-t="1173">and do some other work.</a> <a data-t="1174">The game here is to basically try and last</a> <a data-t="1176">as long as possible before having to compact.</a> <a data-t="1179">That's kind of the game.</a></p>

<h3>Feedback loops and grounding the model</h3>

<p><a data-t="1180">So earlier, Colin talked a lot about feedback loops</a> <a data-t="1184">and as the future of AI.</a> <a data-t="1186">And I agree strongly, tools and feedback loops</a> <a data-t="1188">ground the model in reality.</a> <a data-t="1190">Without it, you know, after a single hallucination,</a> <a data-t="1194">the model just spins off and you've kind of lost it</a> <a data-t="1196">and it does, you know, it goes off the rails.</a> <a data-t="1198">Feedback loops bring it back into the ground.</a></p>

<p><a data-t="1201">A lot of things that are becoming popular</a> <a data-t="1203">in terms of workflows with AI agents,</a> <a data-t="1205">things like test-driven development,</a> <a data-t="1206">again, this is something Colin talked about,</a> <a data-t="1209">planning and implementation phases,</a> <a data-t="1210">using languages with good compilers,</a> <a data-t="1213">Rust and TypeScript with good error messages.</a> <a data-t="1216">All of the reasons that these are becoming popular</a> <a data-t="1218">in the software engineering world</a> <a data-t="1219">is because it grounds the model in reality</a> <a data-t="1221">and it stops it spinning off in one direction</a> <a data-t="1223">and getting lost.</a></p>

<p><a data-t="1224">The same thing happens in kind of,</a> <a data-t="1228">not necessarily software development,</a> <a data-t="1229">but other orchestration and AI agent flows.</a> <a data-t="1233">What we've gone for in particular with Posit Assistant</a> <a data-t="1235">is when we know that the user's doing</a> <a data-t="1237">some kind of data exploration,</a> <a data-t="1240">we kind of trust the model less</a> <a data-t="1242">and bring the human into the loop more.</a> <a data-t="1244">And that is, you know, it's not as deterministic as this,</a> <a data-t="1247">but it's still a way of grounding the model.</a></p>

<p><a data-t="1249">So if you are writing AI agents,</a> <a data-t="1251">what I want you to think about</a> <a data-t="1253">is in your workflow or your pipeline</a> <a data-t="1257">or whatever you're building your AI agent to do,</a> <a data-t="1260">what parts of that workflow</a> <a data-t="1262">can be independently automated deterministically?</a> <a data-t="1266">What can be verified or tested?</a> <a data-t="1268">Think about that, turn it into tools,</a> <a data-t="1270">because then the model can use those tools</a> <a data-t="1273">to stop it spinning off.</a> <a data-t="1274">It keeps it grounded, keeps it on track.</a> <a data-t="1276">Really think about that the best you can.</a> <a data-t="1277">For everything else, if there are things</a> <a data-t="1279">that you know must be true in your workflow,</a> <a data-t="1281">but you can't test for whatever reason,</a> <a data-t="1283">think perhaps there's a time</a> <a data-t="1286">to bring a human into the loop.</a> <a data-t="1287">Software engineering is one of these things</a> <a data-t="1289">where these tools have become very popular</a> <a data-t="1291">because they can run asynchronously and agentically,</a> <a data-t="1294">and they can run, you know, for a very long time,</a> <a data-t="1296">hours in the background.</a> <a data-t="1298">Maybe that's not the case with your particular work.</a> <a data-t="1301">Maybe you need to bring a human into the loop more.</a></p>

<h3>Keeping agents simple and using known protocols</h3>

<h3>Probabilistic debugging and agent guardrails</h3>
