<p><a data-t="2239">So, here you have a classic Positron setup.</a> <a data-t="2242">You have an open R file with a bunch of code.</a> <a data-t="2246">You have a console and a plot pane.</a> <a data-t="2250">And the user here has created a data frame,</a> <a data-t="2252">got some output in a console, and created a plot.</a> <a data-t="2255">So, where does ARC fit in this picture?</a></p>

<h3>Code assistance and the language server protocol</h3>

<p><a data-t="2453">While code execution is certainly a very important part of this,</a> <a data-t="2457">it's not the only piece of the puzzle, or not all pieces of the puzzle.</a> <a data-t="2461">We also think that it's really important to have fantastic</a> <a data-t="2464">code assistance inside of Positron.</a> <a data-t="2467">Now, code assistance just means anything that makes it easier for you to write R code.</a> <a data-t="2472">That could look like diagnostics, where we analyze all the files in your project</a> <a data-t="2477">and can pop up a little tooltip that says,</a> <a data-t="2479">hey, we think something's wrong here.</a> <a data-t="2481">You might want to take a look.</a></p>

<p><a data-t="2484">Code assistance could also look like a function signature,</a> <a data-t="2486">where you're working with SliceMax.</a> <a data-t="2488">You don't necessarily need to remember all of the arguments.</a> <a data-t="2490">We can pop up a signature and say, here, hey, here's what they are.</a> <a data-t="2495">Assistance could also look like jump to definition.</a> <a data-t="2498">Jump to definition looks like this, where you can click on SliceMax,</a> <a data-t="2504">and that takes you straight through to the definition of the function inside of your project.</a></p>

<p><a data-t="2511">Now, these are features that you might have been familiar with in RStudio,</a> <a data-t="2514">but Positron has a number of code assistance features that are unique to it as well.</a> <a data-t="2519">One of those is help on hover, which I really like.</a> <a data-t="2523">It looks like this, where you hover over SliceMax,</a> <a data-t="2526">and you get this really great inline documentation immediately.</a> <a data-t="2531">This is great whenever you're actually just kind of in the flow state of writing R code.</a> <a data-t="2535">You don't necessarily need a whole help pane.</a> <a data-t="2537">You just kind of need to quickly remember how something works.</a> <a data-t="2540">You hover over it, get what you need to know, and you go back to work.</a></p>

<p><a data-t="2546">Now, these features in Positron work in a very similar way as executing code.</a> <a data-t="2552">Code execution worked through the Jupyter protocol.</a> <a data-t="2557">It allowed us to ask questions and send back answers,</a> <a data-t="2561">and code assistance works in the same way.</a> <a data-t="2564">With the Jupyter protocol, that really allowed us to standardize these questions and answers.</a> <a data-t="2569">With code assistance, we used the language server protocol,</a> <a data-t="2573">which standardizes the questions and answers in a very similar way.</a> <a data-t="2576">We ask a hover request of Arc, and Arc can send back a hover response in return.</a></p>

<p><a data-t="2584">The reason that, again, that is so cool is because Arc doesn't care who's on the other side.</a> <a data-t="2589">It doesn't care who's asking the question.</a> <a data-t="2591">It could be Positron, it could be a Jupyter notebook, it could be some other IDE.</a> <a data-t="2595">As long as it implements the other half of the language server protocol, you're in business.</a></p>

<h3>TreeSitter and the R grammar</h3>

<p><a data-t="2601">Over on the right-hand side here, our magic 8-ball, Arc,</a> <a data-t="2604">is doing quite a bit of work to actually send back these responses.</a> <a data-t="2608">Part of the smarts of Arc is wrapped up in a technology called TreeSitter.</a> <a data-t="2614">The only thing you need to know about TreeSitter in this talk</a> <a data-t="2617">is that it takes in all of the R code in your project.</a> <a data-t="2622">We run it through TreeSitter, and it spits out a structured representation of that code,</a> <a data-t="2627">which honestly doesn't even look like R at this point.</a> <a data-t="2630">However, we can use that and power all of the assistance features</a> <a data-t="2634">that we've been talking about today.</a></p>

<p><a data-t="2636">Now, we think TreeSitter is really cool as a project because it works with any language.</a> <a data-t="2641">As long as you have a grammar that teaches TreeSitter how to work with that language,</a> <a data-t="2647">then you're good to go.</a> <a data-t="2649">The problem was we didn't have an R grammar for TreeSitter, so we had to build one.</a> <a data-t="2654">Now, we've built it to work with Arc and Positron,</a> <a data-t="2658">but as it turns out, there's actually a lot of community benefits</a> <a data-t="2661">to having an R grammar for TreeSitter.</a> <a data-t="2664">For example, if you were to bring that R grammar over into Zed or NeoVim</a> <a data-t="2669">or other editors that support TreeSitter,</a> <a data-t="2671">it can power things like syntax highlighting or indentation immediately over there as well.</a></p>

<p><a data-t="2677">And there's also one other big player that uses TreeSitter.</a> <a data-t="2682">It's GitHub.</a> <a data-t="2684">If you've been on GitHub in the past couple weeks,</a> <a data-t="2686">and you've done a search, say, for case when on dplyr,</a> <a data-t="2692">you may have noticed that the search results for R have gotten really, really good.</a> <a data-t="2698">In this case, we found a function called case when.</a> <a data-t="2702">If you click on that function, it will jump you straight to the definition in the project.</a></p>

<p><a data-t="2708">This is just like jump to definition in Positron itself.</a> <a data-t="2712">It's a great way to actually explore a new project</a> <a data-t="2715">without having to pull it down completely.</a></p>

<p><a data-t="2718">The reason this works is because behind the scenes,</a> <a data-t="2720">GitHub code search uses TreeSitter.</a> <a data-t="2723">Now, up until a few weeks ago, this did not work for R</a> <a data-t="2726">because there was no R grammar for TreeSitter.</a> <a data-t="2730">We built one.</a> <a data-t="2731">So we were able to work with the team at GitHub on their code search engine</a> <a data-t="2735">and get them to incorporate our R grammar into their code search engine.</a> <a data-t="2740">And as of a couple weeks ago, it doesn't just work for dplyr.</a> <a data-t="2744">It works for all R projects, cost GitHub.</a></p>
