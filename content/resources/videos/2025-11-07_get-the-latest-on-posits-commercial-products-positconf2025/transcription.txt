<h3>Package Manager authentication</h3>

<p><a data-t="858">So, hi.</a> <a data-t="858">I wanted to talk about one of the newest features that we just released some more support</a> <a data-t="870">for in Package Manager, one that we've been excited about because it's been long overdue</a> <a data-t="875">and one of the most popular requests from many of our customers, is support for authentication</a> <a data-t="879">in Package Manager.</a> <a data-t="879">So, there's several reasons why authentication can be useful in any product,</a> <a data-t="888">especially Package Manager.</a> <a data-t="888">One, for being able to restrict access to repositories that may not</a> <a data-t="894">be wanted to use in a public context, even within your own company, to specific teams or groups.</a> <a data-t="899">The ability to grant more granular access to individual trusted users, your power users who</a></p>

<p><a data-t="992">But, the limitations certainly there of having to manage all those keys manually can definitely be</a> <a data-t="997">an headache there.</a> <a data-t="997">So, with the latest release, we just introduced single sign-on using OpenID Connect</a> <a data-t="1003">and this really allows you to log in with a corporate identity provider that supports</a> <a data-t="1008">OpenID Connect, such as Okta, Microsoft Enter ID, also formally known as Azure Active Directory.</a> <a data-t="1016">But really, I mean, these are two implementations that we've really focused on, but really any</a> <a data-t="1020">OpenID Connect compliant identity provider should work fairly well here.</a></p>
